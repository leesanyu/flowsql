# NPM 分族链路优化分析与方案

2026-10-12；对应 [npm-ip-family-throughput 规格](../tasks/specs/feat-npm-ip-family-throughput.md)。
本轮完成第二轮代码与契约分析，尚未实施优化；下述收益阈值是交付目标，不是已经取得的结果。

## 已确认的成本与测量限制

前置 Feature 的 [成本报告](npm-ip-family-cost.md) 确认活动表/索引堆下降：IPv4 17.35%、IPv6 9.26%、混合 13.32%。
结束快照堆却增加 28.54%～47.56%，未优化构建的插件吞吐下降 1.48%～5.79%。
双方编译含 `-g -DNDEBUG`，没有 `-O`；不能把这些结果作为 Release 基线或生产 SLA。

前一轮隔离诊断固定 CPU 2，真实插件，得到以下结构证据；时间插桩有扰动，仅用于定位路径。

| 证据 | 旧实现 → 当前分族实现 | 意义 |
| --- | --- | --- |
| 51,200 包的临时键分配 | 51,200 → 153,600 | 每包新增具体键对象及 namespace 复制 |
| 同量结束快照分配，含 lease | 51,200 → 153,600 | 独立键和预算控制块抵消紧凑布局 |
| 100 批的视图分配 | 3,400 → 58,600 | Schema 重建、重复校验及地址准备增加工作 |
| IPv4 Basic+Session 编码 | 插桩整体约 67% | 单行 Arrow batch 是输出负载的主要瓶颈 |
| IPv6 持续会话哈希/相等比较 | 402,100 → 419,130 | 当前固定键集的桶分布变差，不能外推全部流量 |

持续会话诊断预热 30,000 个不同端口的 TCP ACK 会话，处理同批五次，共 150,000 包。
计时内无结束/输出，EOF 校验在计时外；每组三个独立进程，版本交替，全部 12 个进程通过。

| 负载 | 旧中位数 packets/s | 当前中位数 packets/s | 变化 |
| --- | --- | --- | --- |
| IPv4 Basic | 183,025.695 | 182,966.407 | -0.03% |
| IPv4 Basic+Session | 165,327.692 | 164,228.699 | -0.66% |
| IPv6 Basic | 168,975.706 | 159,455.052 | -5.63% |

这组批量为 30,000，原 RST 基准批量为 512；两组绝对吞吐不能横向比较。
原 RST 基准的 NPI 解码在计时外；mixed 新旧前台行数不同，不能作为完全相等出口对照。

## 第二轮分析新增的结论

### 会话访问可以复用第一次查找

[ProcessNpmBoundPacket](../src/operators/npm_basic/core/npm_packet_processor.cpp) 先 Observe，再 SampleProtocol。
两者都按同一个键查表；即使 ACK 没有 payload，SampleProtocol 仍先查表，再检查无需采样。
应复用 Observe 取得的短期访问句柄，保持旧实例结束通知 → 采样 → 新实例模块回调的现有顺序。
句柄只在核心同步路径内使用，不向模块发布，不跨下一次表变更；不能把查表消除变成悬空节点访问。
RST/FIN、tuple reuse 和 ICMP 引用仍按各自生命周期验证，不把所有路径强行合成一次查找。

### 临时键无需独立堆对象，但长 namespace 仍有一次复制

[构造函数](../src/operators/npm_basic/core/npm_session_key.cpp) 的栈键经 const 引用复制到 make_unique，造成额外分配。
未启用标签时，按实际族在栈上构造键，让绑定借用它即可；标签准入需跨行暂存，则使用两个具体族键数组。
数组先按实际数量预留，公共行仅保存族与索引；不使用最大尺寸按值 variant，也不重排报文处理顺序。
保留 Key4/Key6 的拥有型 string 和会话身份语义；长 namespace 每个临时键至多一次分配，短字符串无该分配。
C++17 unordered_map 没有标准异构 find，不能声称改成 string_view 就自动实现无分配查找。
本 Feature 不为此新增自定义哈希表或全局字符串驻留；具体键移动构造可用于必要的拥有型转换。

### 地址数组的复制具有生命周期和对齐目的

[批次视图](../src/operators/npm_basic/core/npm_packet_batch_view.cpp) 把 Arrow 地址转换为自然对齐的具体族数组。
缓存 PacketFamilySchema、合并完整验证、缓存子列访问，可以去除重复工作。
地址副本保留并按实际族计费；任意 Arrow Buffer 的地址不能直接 reinterpret_cast 为 C++ 地址对象。
第一版不增加零拷贝 packet ABI，避免把低风险入场优化扩展成新的对象生命周期问题。

### 快照复制是深复制契约，不能只共享旧表键或免计预算

[现有回归](../src/tests/test_npm_basic/test_npm_family_runtime.cpp) 明确验证快照复制后键独立、预算增加且释放归零。
改为批次拥有两族键数组与轻量事件行，批次统一 RAII 计费；生产主链路不再每行分配键对象和 shared lease。
超时/EOF 先完成候选批次的分配、复制与预算准备，再修改水位和删除会话，保持失败原子性。
RST/FIN/tuple reuse 在当前处理批次的族专属存储中准备结束记录，回调仍按原触发顺序执行。
复制拥有型批次必须深复制实际族数组并重新计费；单条独立保留采用显式拥有型复制，不能廉价别名冒充深复制。
仅借用回调视图可以共享读取；视图不跨所属拥有型批次的生命周期或未冻结数组扩容。

### 输出收益同时来自批量编码和避免无出口编码

[结果收集器](../src/operators/npm_basic/output/npm_basic_result_collector.cpp) 已有批量编码器，却在 router 路径逐行调用。
首版复用这些编码器：四个 Basic/Session 具体族缓冲有界积累，按实体编码一批并调用一次 Emit。
前台仍使用单个 pending builder，按批追加并 Finish，不引入全量结果二次拼接；不承诺消除全部列复制。
观察输出与 consumer 同时存在时，一份编码 batch 服务两个出口；全部托管实体仍必须交付。
每实体至多 512 行，总 typed 暂存容量软上限 1 MiB；容量、string 和编码/绑定峰值都进入现有任务预算。
软上限在接收下一行前触发排空；单行超过软上限则直接编码路由，仍受默认硬预算约束。
typed 结果和 UTF-8 先校验；Basic/Session 中既不观察又无 consumer 的实体不构造 Arrow，模块事实处理仍执行。
协议模块的既有 Emit 接口保持同步校验/消费/复制；其解析器和私有编码器不重写，不承诺消除已经发生的编码。

### 缓存增加后必须补齐真实排空边界

[运行时](../src/operators/npm_basic/core/npm_basic_task_runtime.cpp) 的 should_emit 不能只看前台 pending 行。
新的 pending 状态必须包含非观察实体缓存；ProcessBlock 返回、时间维护、正常终结前均排空已接受行。
发布前验证 typed 缓冲、consumer 待写及前台 pending 均已完成，不能仅以源水位构造写入成功证明。
Finish 在末批编码/Consume 成功后执行；写入/发布失败或状态未知立即终结，保留实际提交前缀。
取消/失败只清理尚未交付的数据，不追加 EOF 结果；standalone collector 的失败可重试与输出不变保证保留。
各实体内行序与 revision 保持；跨实体提交次序不形成新的全序或跨表事务保证。

## 收敛后的实施路线

| 阶段 | 交付 | 验证收益或保证 |
| --- | --- | --- |
| T1 | 当前分族版本的 Release 基线、内部数据契约、测试锚点 | 两边同配置、同流量、同出口，能够归因 |
| T2 | 缓存 Schema、一次完整入场验证、借用绑定、复用会话访问 | 临时键无独立对象分配，持续 ACK 一次逻辑会话查找 |
| T3 | 分族拥有型结束批次与统一预算 | 无逐快照控制块，深复制、持有期、失败原子性保留 |
| T4 | Basic/Session 有界批量编码、出口选择和排空接线 | 编码/Consume 按批发生，所有托管实体及进度正确 |
| T5 | 真实插件吞吐、成本及完整回归 | 达到性能目标且容量、预算、存储和生命周期无退化 |

不单独开启当前版本的 -O3 作为优化结果，不更换哈希函数去拟合连续端口样本。
不移除输入/结果校验、预算锁或深复制来制造收益；不预留 IPv6 最大键，也不放宽默认预算。
不引入通用内存池、异步 consumer、并行 worker、新的采集后端或数据库事务协议。

## 性能与正确性验收设计

主基线是实施前的完整分族工作区快照，包括未提交文件；记录源清单、编译参数、依赖和 .so 哈希。
旧 e577023 版本仅作辅助历史对照，不能替代同一新 Schema、相同出口的优化前基线。
两边通过 `src` CMake 入口构建独立 Release 目录，复用主工作区第三方缓存；基线不依赖易失的 /tmp 副本。
固定 CPU、96 字节、模块、批量、预算和输出目的地；每组预热后至少七次独立进程，版本交替。
pps 主计时包含处理、必需排空和输出释放，等价校验单独统计；另报含校验的旧口径及端到端解码口径。
报告中位数、范围、CPU 时间、分配/字节、预算峰和 RSS；阶段计时只作归因，不累加嵌套 scope。

| 负载 | 覆盖与交付目标，相对同配置分族基线 |
| --- | --- |
| 512 行 RST 结果负载 | 三种族分布 × 两种模块；每组 pps 至少提升 20% |
| 30,000 活动会话 ACK | 三种族分布 × 两种模块；每组 pps 至少提升 10% |
| 更新活动会话 | 地址/端口多样化、时间递增、payload、双向、标签开关；每组不下降超过 3% |
| 周期、超时与 EOF | 30,000 会话四生命周期 × 四族/观察组合；默认容量/预算内全部结果可交付 |
| 托管结果 | 四后端、全部 12 实体、同一前台选择；正确性全通过，性能按后端报告 |

阈值是 Feature 完成门槛，未达到不得仅凭结构计数宣布完成；不把数据库网络吞吐写成固定机器无关 SLA。
差异落在采样波动内时不判通过；在相同条件下增加有效处理时长或稳定复测，不放宽门槛。
前三类无存储负载同时校验实体内顺序、全局 ID、revision、标签/协议/周期事实和两族地址值；只排除实际 run 标识及生成时钟差异。
混合前台观察同一具体族；托管模式比较全部实体，不能通过减少输出行数或禁用模块取得收益。
确定性测试覆盖短/长 namespace、碰撞键、双向端点、tuple reuse、跨批次复制与销毁、预算拒绝及保留 Array/Buffer。
运行完整 CTest、四后端实际存储回归及 ASan/UBSan/LSan；阶段切片只运行对应验收，不提前扩大范围。

## 方案审查重点

契约审查一轮收敛：临时/标签键扩容失效、访问句柄被删除、快照候选失败后部分修改、缓存未排空却发布进度，
以及保留 Arrow 结果后 allocator 或插件提前销毁，是本 Feature 必须用测试拦截的内存/生命周期与一致性风险。
性能不达标以同口径日志继续定位，不扩大 Feature 到并发重构或一般性数据库/协议优化。
