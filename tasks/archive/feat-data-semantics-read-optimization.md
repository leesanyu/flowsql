# Feature：静态说明读取与展示优化（data-semantics-read-optimization）

状态：`[x]` 已完成；优先级：P1；立项日期：2026-11-19；完成日期：2026-11-20。
依赖：[说明管理](../archive/feat-metadata-description-query.md)、[算子说明](../archive/feat-operator-description-refinement.md)、[NPM 领域说明](../archive/feat-npm-data-semantics.md)及既有标准/字典/契约基础。
所属 [数据说明 Epic](../specs/epic-data-semantics-dictionary.md#data-semantics-read-optimization)；实施优先处理静态读取，再交付通用页面；原 Feature 完成事实保持。

## 业务意图与 Non-Goals

让频繁阅读说明的用户、任务执行器和未来模型调用方，快速取得标准、字典与算子契约，避免数 KB 摘要因反复读取、解析 MB 级静态定义而等待秒级时间。
同一对象说明链路同时提供完整、分层且对齐的 Web 阅读体验：使用者能找到已声明字段、条件和关联，局部规则与完整 JSON 可取得，人工补充独立保存。
交付重点是静态定义热读接近内存访问成本，并削减任务准备中的重复语义工作；数据库结构等实时事实的核验开销分别测量。

- 不新增领域指标、分析算法、语义规则语言、存储引擎、跨进程缓存服务或第二套模型元数据；不把描述条件升级为可执行聚合/JOIN。
- 不交付模型/MCP/Skills 接入、SQL DESC、结果/图表就地说明或全站视觉改版；相关能力分别归模型诊断及 Epic F5。
- 不缓存过期的组件身份、current 指针、对象绑定或真实结构来换取速度，不跳过边界校验、吞错、增加同步超时或把元数据失败当成功。
- 不要求旧 API/ABI、页面草稿或存储格式兼容；需要变更时同步接口、Schema、调用方、测试和说明，产品中只维护当前实现。
- 不扩展数据库/采集/认证/容器矩阵；只对下文声明的路径验收，不用全量测试或真实模型运行替代针对性证据。

## 问题依据与 Feature 边界

2026-11-19 的实际 HTTP/Chromium 检视发现：NPM usage 8,256 bytes，读取约 1.326 秒；完整契约约 3 MB，局部资源读取约 0.446 秒。
两次有限 PCAP→SQLite 十二实体任务总耗时 15.66/12.88 秒；这些是历史诊断样本，不是语义独占耗时、稳定分位数或性能回归阈值。
注册表精确读取仍在共同锁内取全文、解析及验摘要；现有 producer-contract 缓存仅覆盖部分路径，usage/resource 仍可能重复处理整份契约。
页面实际有五项参数和五个详情引用，但作者短说明使输入/参数/输出区域均为零字段行、零结构详情入口；字典有已声明角色/度量类型却缺少常规展示位置。
1440px 下字典四列未错位；本次解决信息缺位、密集重复和多尺寸布局，不把已验证正常的列对齐描述成已复现缺陷。
依据为[本地检视报告](../../evidence/npm-data-semantics/review-20261119/review.md)及同目录原始响应、耗时和截图（未入库）。规格不依赖缓存存在才能定义验收。

读取加速与页面改造沿同一“对象→说明→局部规则/全文”主链路交付，共用精确版本和内容完整性验收；不拆出独立缓存平台或重建高级字典产品。

## 核心数据与接口契约

### 静态定义与动态依据

| 数据 | 核心结构与责任 |
| --- | --- |
| 定义快照 | 复用 `DataSemanticsSnapshot` / `OperatorContractSnapshot` 的 `exact_reference`、`schema_id`（适用时）、`sha256`、拥有型不可变 JSON；标准、字典及作者契约一视同仁 |
| 已解析定义 | 注册表实例内按精确引用关联已校验原文、不可变解析结果；内容摘要标识同一事实，派生视图不能改变原文或凭名字套用其他版本 |
| 静态阅读投影 | 按所属精确定义与 `view/resource_pointer` 关联 usage 的作者部分、字段页和局部资源；只生成请求需要的投影，full/export 才组织全文 |
| 动态阅读依据 | 继续使用 `basis`、当前组件/说明引用、`object_key`、来源修订、结构指纹、binding/field_map；每次从原权威入口取得并与静态投影合成 |
| 页面与下载 | 共用现有 `usage/details/description.document` 和完整文档；页面分组、展开状态及编辑草稿不构成另一份作者契约 |

- 对外沿用 `/api/semantics/v1/` 下的 `describe/resolve/export`、保存及检查接口；进程内仍按 IID 查找，不依赖 Config 具体类或直接操作其 SQLite。
- 静态内容在注册/首次装载时完成解析、结构及摘要校验；成功提交后才发布缓存。热读复用不可变快照，不重新查定义正文、解析全文、算摘要或扫描全量资源来生成小响应。
- 随插件注册的静态作者契约在组件可用时应已具备上述读取能力；不能把旧的秒级工作全部转移成首次打开页面的隐形预热，注册/服务就绪耗时也要记录。
- 缓存按保留字节有界，覆盖原文、解析结构及投影；T1 编码前在内部头文件与测试中冻结预算及淘汰规则，不按请求无限积累局部投影，不用定期 TTL 代替版本一致性。
- 并发首次读取同一精确定义只发布同一有效结果；共同锁不包围大文档解析、投影及 HTTP 序列化。保存事务仍保持 current/引用/绑定一致性。
- 保存新修订不覆盖旧快照；组件替换及本地说明保存后，下一次当前读取采用新依据，历史精确读取仍返回原文。版本切换覆盖 @1→@2→@1，不能用名字或 latest 作为缓存键。
- 关闭/重开注册表、切换存储实例及插件卸载时清理所属缓存；已返回快照拥有自身内容，引用被淘汰不悬空，不借用已卸载库资源；读取失败不回传上一次成功内容。
- 可变身份、来源结构和字段映射继续执行原核验；有声明却不可读仍报错，missing/unknown/undetermined 及部分成功含义保持明确。页面草稿不因后台刷新被覆盖。

### 系统化页面展示与 JSON

| 区域 | 默认可读内容 | 分组详情与完整性要求 |
| --- | --- | --- |
| 算子概览 | 名称、用途和来源可辨的本地补充 | 组件摘要、精确引用和历史折叠，Python 源码仍在说明入口之前 |
| 算子输入 | 端口、数量/形态和已声明字段/角色要求 | 必需性、类型/可空性、参数字段映射、结构资源；指向 `/resources/` 的详情也可达 |
| 算子参数 | 作者参数名、类型/编码、必填和默认提示、简短说明 | 范围/枚举、互斥及组级条件、嵌套 JSON 配置；声明默认值不自动提交 |
| 算子输出 | 前台实体选择与托管集合的区别、输出摘要和可确定字段 | 产生条件、variants、动态结构、行类别/NULL、上下文及资源引用；未确定分支仍有入口 |
| 字典对象 | 对象说明、一行含义及行语义 | 身份字段、修订字段、时间字段集合、局限及去重后的联合关联；内部依据不塞入日常正文 |
| 字典字段 | 名称/类型/可空性、单位/时间、含义 | 标题、角色、度量类型、NULL、有效性、聚合、枚举/值域、标准引用和完整复杂时间定义均有位置 |
| 技术与下载 | 按需取得局部规则、完整文档及 JSON 下载 | 已保存读取与未保存草稿分清，引用、状态、origin 和 64 位整数无损保留 |

- 作者短说明与结构表同时存在；本地输入/参数/输出说明表不替代作者结构，未填写本地补充时仍显示已知要求。同名本地文字不自动改变作者类型、必填、默认值或规则。
- 一套通用组件覆盖内置、C++、Python 算子及数据库、DataFrame、结构化 Kafka 对象；不按 `npm.basic` 名称特判。NPM 与 Baseliner 的复杂输出按所属端口/实体分组，避免十二实体一张宽表。
- 摘要、字段表、所属分组详情、原始 JSON 四层可达；复杂规则允许保留局部 JSON，但不能只在最底部大 JSON 中寻找调用所需的参数或已知条件。
- 字典继续采用紧凑主行、说明与按需详情；联合关联在对象级完整呈现，字段处导航到该关系，避免每个成员重复一整段映射。限制与人工正文分区，长正文自然展开或明确展开，不靠小文本框内部滚动阅读。
- 缺失、未知、不适用与已声明但折叠可区分；保存前后隐藏字段保持，作者/本地/导入来源可辨。刷新、对象切换、历史及冲突保护原有草稿和依据。
- 阅读只请求当前摘要；展开局部规则才请求对应精确 resource，展开全文/主动导出才取完整契约。不会先下全文再隐藏；阅读不加载 CSV 行、不预览业务数据、不消费 Kafka、不运行算子。
- 具体对象和算子面板直接提供“下载字典 JSON / 下载契约 JSON”，复用现有 export 的 `kind/name/source_reference/document` 信封；复制读取响应与导出文档分别标明，契约不混入本地补充。
- `producer_default` 尚无独立字典引用时可下载 `description.document` 的标准 JSON 原文，并标明未独立保存；不能为导出创建绑定或伪造 source_reference。需要依据时另可复制带 basis 的读取响应。
- 导出采用最近成功读取的已保存版本，不含未保存草稿；核对过期版本按精确引用读取，不自动导出 latest。不递归打包依赖、不另造交换格式，原 JSON/YAML 导入导出继续可用。

## 两条主链路

1. **快速阅读与维护**：组件注册/首次读取建立有效定义 → 当前对象取得动态依据 → 复用同版本静态摘要 → 页面或普通 HTTP 客户端读取 → 按需取精确详情/全文/下载 → 显式保存人工补充后重新核验依据；历史精确引用保持。
2. **任务准备与分析**：解析实际参数与来源 → 复用静态契约及本次有效元数据快照，核验组件/真实结构并发布必要字典绑定 → 运行原分析数据面 → 记录真实结果依据；分段统计准备/首包/运行/结束成本，失败保持原数据及元数据状态。

## 验收契约

### 性能与一致性

- **A1 静态热读**：对标准、字典和约 3 MB 的 NPM 作者契约，预热成功后同版本 IID Resolve 的定义正文查询、全文解析、摘要计算次数均为零；调用次数增加不增加这些计数。新版本、冷装载和淘汰后重新校验分别有断言。
- **A2 公共小响应**：同机回环生产 Web→Gateway→Router→Config 路径，标准/小字典精确读取、NPM usage、局部 resource 和字段投影（选中响应≤64 KiB）的串行热读 p95 各不超过 100 ms；IID 精确快照热读 p95 不超过 1 ms。已定位慢路径的 NPM usage/resource 相较同次优化前基线，p95 至少下降 80%；不把 full/export 的传输字节计为小响应。
- **A3 并发与生命周期**：同一精确定义及不同小定义的 8 并发读取无重复首次发布、内容串用或崩溃；大定义读取不触发其他热读重新查正文/解析。缓存淘汰、保存冲突、注册表重开、插件替换/卸载与存量快照拥有期均通过断言；缓存自身保留字节不超过 T1 冻结预算，外部仍持有的快照独立统计，不以提前销毁引用者内容满足预算。
- **A4 当前事实**：更新组件、本地补充、绑定或真实结构后下一次读取反映新依据；历史原文不变，来源冲突/不可用不返回旧 matched。相同内容的不同存储实例不能混用信任状态，非法输入及冷装载完整性错误仍明确失败。
- **A5 任务开销**：十二实体 PCAP→SQLite 托管 37 对象的重复运行，语义准备阶段耗时中位数相较同环境基线至少下降 70%；分别统计契约检查、逐对象核验/发布、使用记录，不把任务总时间作为该阶段耗时。首次创建与重复运行分别报告；业务字段/行数一致，引用正确对应各自运行且可精确解析，人工补充不变，独立生成的 run/task/use 身份不要求字符串相等。
- **A6 数据面**：对同配置混合 IPv4/IPv6 受控离线/实时输入，持续处理段不出现静态定义读取/全文解析，输出及终态与基线相同；稳态吞吐相较基线下降不超过 5%，首包等待及周期交付 p95 分段报告。不以增加超时、减少实体/校验或跳过失败换达标。

性能比较使用同环境、同构建类型、相同配置/输入及固定负载；实施前先固化基线，完整记录源码/产物摘要、CPU/内存、执行位置、请求字节和计时边界。
小响应预热 5 次后每项采样 100 次、并发场景至少 100 次完成请求；任务准备至少 5 次、数据面至少 5 轮交替运行基线/候选。冷读、组件注册和服务就绪单独报告，不混入热读，也不省略冷启动回归。
计时断言进入专用性能 target，确定性工作计数/内容断言进入常规单测；阈值未达标保持未完成，不能事后放宽阈值收口。生产路径不常驻逐包计时日志。

### 页面、导出与调用基础

- **A7 算子完整展示**：真实 NPM 页面五项参数及输入/输出精确详情均可达，不受短说明/本地空表影响；Basic/Session/协议两族资源完整，主输出与托管集合可区分。Baseliner 条件输出/NULL、简单内置及 Python 多样声明通过同一组件，无名称分支。
- **A8 字典覆盖**：按上表逐项播种已声明值并检查对应位置、未知/不适用及复杂时间；NPM 十二实体 358 分析字段的原文内容完整。身份/修订/时间集合、角色/度量/标准引用可读，联合关系只完整列一次且各成员可导航。
- **A9 真实浏览器**：在 1440×1000、1024×768、390×844 分别检查表头/单元格对齐、长字段/说明、弹层和横向溢出；必要表格在容器内滚动，操作可点击，正文无意外裁切。页面保存/取消/刷新/历史/切换/版本冲突不丢草稿，作者契约不被补充说明改写。
- **A10 按需读取与下载**：浏览器请求记录证明默认不请求 full、无业务行读取/执行；所有相关 resource 与当前精确引用一致。保存前后补充以外的字段逐值相等，旧引用保持；绑定字典/producer_default/契约下载成功，JSON 64 位数值无损，导出文档与对应精确读取逐值相等。
- **A11 程序消费**：普通 HTTP 客户端从 usage→details→同版本 resource→显式预检形成闭环，Schema/OpenAPI 校验通过；已知条件、编码、必要上下文及未知状态保持，预检与运行记录不因缓存改变结论，不要求实际模型接入。
