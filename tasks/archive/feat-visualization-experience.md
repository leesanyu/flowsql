# Feature: 数据库探索体验优化

标识：`visualization-experience`；优先级：P1；状态：`[x]` 已完成（2026-10-21）。
前置：[基础探索与 Web 入口](../archive/feat-visualization-database.md)、[多数据库探索兼容](../archive/feat-visualization-database-connectors.md)。
用户已授权按 T1→T2→T3→T4 连续实施，每项完整验收并标记后再开始下一项。

## 业务意图

让探索 SQLite/MySQL/PostgreSQL/ClickHouse 数据表的用户，以画布为主完成日常绘图，分别保留多张表的图表与过滤配置，
使用一致的图表编辑入口，并能绘制常见 Decimal、识别精度近似及在失败后继续调整配置。

已核查的当前问题：两组数据的柱图在 1440×900 窗口仅约 84×270 像素；切表返回后原图清空；原生推荐修改图表后
顶部控件不同步；Decimal `0.1` 被完全无损规则拒绝，且原生组件弹出英文计算错误框。以上为整改前基线，不是完成证据。

## Non-Goals

- 不新增跨表/跨库 Join、SQL 编辑器、DataFrame、分箱、直方图、时间桶或去重计数能力。
- 不交付跨刷新/重启的图表持久化、共享仪表盘、同屏多图拼版或多用户协作；本期为会话内按表独立工作页。
- 不更换或维护 Graphic Walker 分支，不扩展 C++ 插件虚表，不改变原生 SQL 计算、只读权限和源时区语义。
- 不改用户账号、业务数据或部署，不接管既有运行进程；不默认执行无关 Kafka、镜像或产品全量测试，不提交推送。

## 契约与核心结构

### 工作页与图表状态

```ts
interface TableWorkspaceV1 {
  source_id: string;
  schema_revision: string;
  chart: IChart;                      // 唯一图表配置，含字段映射、聚合、过滤和布局
  editor_mode: 'simple' | 'advanced';
  detail_mode: 'complete' | 'limited';
  temporal_field?: string;            // 沿用用户显式选择规范 UTC 时间轴
  request_generation: number;
}
```

- 工作页按服务端 `source_id` 隔离，保存其 `schema_revision`；同名表按既有来源身份区分，同表重复打开定位已有页。
- 各页保留自己的图表、过滤、明细/时间选项和编辑模式；A→B→A 恢复 A 的配置，禁止沿用 B 的字段或结果。
- 只计算当前可见页；切页、关闭页和宿主隐藏时取消对应在途请求。响应必须同时匹配来源、schema 和请求代次才可更新 UI。
- 关闭工作页释放状态与请求；来源消失或 schema 改变时明确提示刷新/重新选字段，禁止把旧字段 ID 静默套到新结构。
- `chart` 是唯一配置真相；简洁控件、原生编辑和图表推荐均从它读取并更新，不另存一份可覆盖当前图表的旧配置。
  简洁控件无法完整表达的高级配置应保留；切换模式本身不得隐式修改字段、过滤或聚合。

### 布局与交互

- 独立入口与 Web 嵌入入口沿用同一工作区、主题与显隐契约；默认简洁模式，主路径为选表→选字段/图表→绘图。
- 常驻区只保留表工作页、必要绘图控件和紧凑结果状态；过滤、明细、时间等设置按需展开，原生拖拽界面从“高级编辑”进入。
- 数据库方言、字段原生类型、时区/排序及能力说明放入信息入口，支持悬浮、键盘聚焦和点击查看；长字段清单不常驻顶栏。
- 默认简洁模式在 1366×768、1920×1080 桌面窗口中，绘图区宽度至少占工作区宽度 85%，高度至少占工作区高度 70%
  （工作区不含宿主导航）；实际 canvas/SVG 随容器适配，禁止只扩大外框而图形仍按两组数据缩成狭窄小图。
- 高级模式推荐面板默认折叠、可主动展开；解释其用途为根据所选字段调整当前图表，应用后图表状态与可表达的简洁控件同步。
- 本期快捷图表为柱状、折线、散点；推荐入口仅开放当前已交付能力，未支持的分箱、时间桶等操作应禁用并可查看原因。
- 全量/Top-N/受限明细及近似精度标记始终可见；空白、加载、失败有明确状态。错误使用中文内联提示及可操作建议，
  保留图表配置、允许修改后重试；不再弹出重复的原生英文 `Oops!` 计算错误框，不能把失败伪装成成功空结果。

### Decimal 绘图与精度

本规格实施后替代旧探索规格中“Decimal 必须完全无损才能绘图”的约束；原归档保留历史事实。
沿用 HTTP API v1 和数据库会话接口，计算响应新增可选精度元信息，既有 `rows`、`scope` 等字段不改名、不改类型。

```ts
interface NumericDisplayV1 {
  field_id: string;                   // 计算结果中的字段 ID/聚合别名
  mode: 'exact' | 'approximate';
  origin: 'decimal' | 'native_decimal_mean';
  exact_values?: Array<string | null>; // 与 rows 同序；原生精确 Decimal 结果必须保留文本
}
// ComputeResponseV1 新增 numeric_display?: NumericDisplayV1[]
```

- Decimal/PG Numeric 先保留源库精确文本，再为绘图生成 Float64；`0.1`、`0.10000000000000000001` 可近似绘图，
  明确标记 `approximate`，精确文本可从结果信息查看；`1.5` 等可精确表达的 Decimal 标记 `exact`。
- 非零值转为零、非有限值或数值超出既有安全量级 ±9007199254740991 时明确拒绝；超安全范围整数继续拒绝定量绘图，
  不得因聚合先转浮点绕过保护；原生浮点字段沿用源库语义，不宣称十进制精确。
- 投影、sum/min/max 及 MySQL/PG Decimal mean 以源库精确结果转换；ClickHouse Decimal mean 原生返回 Float64，
  允许在安全范围内作为 `native_decimal_mean` 近似展示，不伪造精确均值文本，也不下载整表重算。
- NULL 保持 NULL；精度元信息随结果完整返回并计入既有字节预算，超限明确失败，禁止截断精确文本后声明无损。
- 原生 SQL 过滤/分组仍使用源类型；浮点转换只用于返回后的数值展示，不把近似绘图值写回数据源或用于替代源库统计。

## 主链路

1. 选择数据表→发现字段/结构版本→打开或恢复对应工作页→编辑唯一图表配置→当前页执行原生查询→画布填充可用空间；
   切页/隐藏/关闭→取消旧请求→代次隔离响应→恢复所选页配置。
2. workflow→校验字段/能力/只读与预算→原生 SQL→Decimal 精确结果与绘图数值/精度元信息→图表及精度提示；
   不支持/超限/查询错误→中文提示并保留配置→调整后重新执行。

## Feature Tasks 与验收锚点

- [x] **T1 — 用户通过以画布为主的简洁界面与一致的高级入口完成绘图，减少常驻信息和重复操作。**
  验收：真实浏览器在两种桌面尺寸、独立/嵌入和明暗主题中断言绘图区占比、实际图形缩放及无页面横向溢出；
  信息入口支持悬浮/聚焦/点击；推荐折叠、能力禁用、简洁↔高级及推荐→简洁状态一致，无旧控件回写覆盖。
- [x] **T2 — 用户可在同一会话为多张表分别保留图表，切换和关闭工作页时配置与查询结果互不串扰。**
  验收：A 绘柱图、B 绘折线、A→B→A 保留字段/过滤/聚合和模式；跨来源同名表隔离、重复打开定位原页；
  延迟响应、切页/关闭/宿主隐藏取消、来源消失/schema 改变均有机器断言，隐藏页不持续计算。
- [x] **T3 — 用户能绘制常见 Decimal 并辨识近似精度，在数值或查询失败后保留配置并恢复操作。**
  验收：三库真实 API/原生 SQL 对照及浏览器覆盖 Decimal 投影/聚合，含 0.1、1.5、高精度小数、NULL、CH Decimal mean；
  大整数及聚合绕过、非有限/下溢、精度元信息字节预算有边界断言；错误为中文且不重复弹窗，调整字段后可恢复成功图表。
- [x] **T4 — 用户获得一致的四库探索体验、可复现使用说明和完整的受影响范围验收证据。**
  验收：SQLite/MySQL/PG/CH 的柱状/折线/散点/过滤、原生统计对照与 T1～T3 场景统一回归；
  入口/桥接、取消/上限/资源回收和共享 workflow 契约保持；用户说明明确会话保存边界、推荐用途、近似精度和错误恢复。

- 当前按用户授权进入实施；规格立项检查不计入产品验收，完成任务必须有本轮执行证据。

- 实施基础清单为全部 `test_visualization_*`（覆盖入口、浏览器计算、客户端、预算/资源、交付及三库适配/E2E）；
  新增体验用例同切片纳入标准测试入口、依赖声明及资源锁。仅当实际修改数据库共享契约/驱动时追加对应驱动或快照回归。
- 构建仍以 `cmake -B build src` 为入口；具体 target、所需测试产物和筛选命令在实施工作台冻结，不在规格中固定临时路径。
- 外部数据库账号、地址、凭证与专用库统一读取 `config/testing/environment.json` 或其显式运行时副本，依赖见
  `config/testing/dependencies.json`；从实际执行位置 doctor 验证认证/目标库，读写操作权限由隔离 fixture 独立验证。

  缺依赖必须非零，禁止跳过计通过；不更改用户配置/容器/卷，不重启既有服务证明产物已生效。
- 全部 Task 完成后再归档、标记 Backlog 完成；源码、构建产物与实际运行服务的验证边界分别记录。
