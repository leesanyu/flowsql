# Feature：受控数据与 MCP 接入（agent-data-access）

状态：`[x]` 已完成，A1～A9 整体验收通过；优先级 P1；创建日期：2026-11-25；更新日期：2026-11-27。
所属 [诊断 Epic](../specs/epic-llm-skill-diagnosis.md)：F1；依赖已有对象说明、SQL 执行及探索能力，无本 Epic 内前置 Feature。

## 业务意图与 Non-Goals

让普通程序及内外 Agent 从同一接口发现 FlowSQL 各类通道、理解语义和实际能力，按授权范围查询或执行声明的分析操作，
获得有界、可取消、有实际计算依据的结果，不必取得底层存储凭证或绕过 FlowSQL。
MCP Server 是跨业务复用的数据接入服务；NPM/DNS 是其中一个验收场景，普通业务表、DataFrame 等无需加载 NPM 即可使用。

- 不交付诊断推理、Skills、聊天界面、永久证据/报告存储或导出；产物写入由 F2 承担。
- 不提供任意业务写入、配置修改或自动修复，不将“SELECT”前缀作为只读证明。
- 不重写数据库引擎、元数据模型、NPM 算法或通用身份平台；复用既有运行能力并补齐边界约束。
- 不把 MCP 工具标注、模型 Prompt 或客户端声明作为服务端授权依据。
- 不把所有通道包装成可执行 SQL 的表，不因通道可发现就开放消费、采集或写出；本期不新增持续订阅、实时采集控制或原始报文下载。
- 不将整个 Feature 强制为 Python，不引入 Agent SDK 承担 MCP 协议适配；Python 优先用于独立 MCP 接入层，须经下述最小验证后冻结，不以 Worker 内脚本或 Agent 内模块代替。

## 核心数据与接口契约

公共契约已经冻结为工具 JSON Schema、MCP 输入/输出及共享计算头文件；只维护当前契约。

当前实施已冻结 [工具 JSON Schema](../../config/agent-data-access/api.schema.json)：普通 HTTP 使用独立受控监听器的
`GET /data-access/tools` 与 `POST /data-access/call`，C++ `flowsql_data_access` 插件持有策略、操作、预算和结果。
查询采用结构化单来源 workflow、服务端绑定参数与计算前策略过滤，不接受原生 SQL；DataFrame 需显式取得快照。
主体来自部署方配置的服务受众专用 Bearer 凭证；MCP 入站凭证映射到同主体的独立下游凭证，不接受客户端身份头。
结果采用 NULL 或 `{type,value}` 无损单元格（int64/float64/Decimal 为文本、二进制为十六进制），分页附固定摘要和复制原文；
读取租约最长 5 分钟。任务/结果由 FlowSQL 持久化，MCP 断连不取消任务，业务取消通过 `cancel_operation` 核对终态。
语言冻结为独立 Python 包、官方 MCP SDK `>=1.30.0,<1.31`、Streamable HTTP `2025-11-25`；静态凭证部署不建设通用 OAuth 平台。
已完成最小安装/真实客户端契约夹具验证，其他能力仍依下表及 A1～A9 完整验收，不缩减原验收范围。

| 数据 | 核心内容与保证 |
| --- | --- |
| `AccessScope` | 已认证主体、允许通道/对象/时间/操作和派生目标、结果与执行预算；由服务端权限和用户授权共同确定，模型只能申请不能自授 |
| `SourceRef` | 资源类别、provider、真实对象身份与 locator、适用的通道类型、数据形态、source/sink 等角色、结构及运行/快照/配置修订依据；不以展示名或 NPM 表名推导身份 |
| `SourceCapabilities` | 逐操作声明支持情况、可用状态与原因、输入/输出约束、必要预检、有限性及副作用；能力存在不等于主体获准，不支持与依赖暂不可用分别表达 |
| `OperationDescriptor` | 查询或算子的真实身份、输入/参数/输出契约、限制和说明依据；复用已有算子说明，工具接口不枚举 DNS 等业务指标 |
| `QueryRequest` | 单来源引用、结构化 workflow、范围、预算与请求身份；分析选择部署方固定方案，冻结真实算子、参数、精确配置引用和主体独占输出，不接受原生 SQL、连接串或宿主路径 |
| `QueryResult` | 任务/请求身份、类型化数据、行数与范围、全量/Top-N/采样/截断状态、单位、执行时间、实际查询/参数和说明依据 |
| `ResultRef` | 主体范围内的不可变结果身份、结构/内容摘要、行数/字节数、观测依据与过期时间；分页和 F2 转存固定同一结果，不是数据库地址或访问凭证 |
| `OperationStatus` | 稳定请求/操作身份、参数摘要、关联任务、实际状态和错误阶段；包含取消请求中、状态待核对及中断，不能将断连或未知冒充成功/已停止 |

- 能力面覆盖来源/操作的发现与描述、按需预检、提交、状态、取消及有界结果读取；工具按这些通用动作组织，以来源引用和操作参数选择能力，不为每个领域或通道复制一套工具。
- MCP 负责工具注册、协议处理、入参校验、认证接入、HTTP 调用及结果转换；经公开 HTTP 调用 FlowSQL 受控数据能力。通道发现/说明、业务授权、预算、任务状态/取消及结果管理由 FlowSQL C++ 服务和插件负责，普通 HTTP 客户端调用同一业务入口；查询、算子执行和批量传输沿用既有运行链路及数据面。
- 远程 MCP 使用 [Streamable HTTP](https://modelcontextprotocol.io/specification/latest/basic/transports)；T1 冻结所用协议修订、SDK、认证方式和委托范围，并按官方[授权契约](https://modelcontextprotocol.io/specification/latest/basic/authorization)核验真实客户端互通。
- MCP 校验入站身份和令牌受众；向 FlowSQL 传递可验证的主体与受限委托，不把入站令牌直接透传给不同受众的下游，不靠可伪造的主体字段或共享高权限账号扩大权限。
- T1 冻结可运行的身份来源、主体映射和部署方配置的最小授权策略；提供受控入口所需的校验与拒绝能力，不假设现有 Web 已有完整权限平台。受控客户端不能同时绕行未受保护的 SQL/任务入口，部署说明和负向验收覆盖此路由边界；F2/F4 复用主体身份并各自校验产物/会话权限。
- 认证信息不进入 Prompt、工具参数、结果或审计日志；具体来源能力按下表验收，不能从共享接口推断已支持。
- 来源发现和描述只读取授权元数据，不隐式加载 DataFrame、读取业务行、消费消息、提交位点或打开采集设备；缺少结构/说明明确返回未知。
- NPM 公开关系按真实身份和元数据发现，不能改用内部表绕过 `history/latest/final` 语义；NPM 的字段、有效性和修订规则由领域说明及算子契约提供。
- 查询限制在执行端落实：对象、时间、参数、语句类型、预算和取消；数据库通过实际只读会话执行，分析单独遵循声明算子契约。
- 各后端使用同一结构化查询子集，SQL 由服务端生成并绑定参数，不开放原生 SQL、任意表达式/函数或写出路径。时间条件在计算前作用于每个受限来源，不以返回行数限额替代扫描/执行预算。
- 需要算子时单独预检并提交获准的有限分析，输出写入受管派生结果范围；禁止覆盖业务来源或把分析写出伪装成只读查询。
- 仅提供声明且可验证的统计能力；比率、分母、时间桶、分位数或去重若被声明，必须确定有效条件并有独立数值断言。
- 结果读取具有明确寿命和失效错误；永久保存交给 F2。F2 通过受信任的结果身份取得数据及来源，不接收模型伪造的执行事实。
- 结果分页、转存和重读使用同一 `ResultRef`；T1 冻结 NULL、大整数/Decimal、时间单位/时区及二进制的无损编码。F2 在过期前取得受限读取租约并完成整份选定结果的复制/摘要核对，成功后解除临时租约；失败不发布半份证据，已过期不重新执行原查询补造数据。
- F1 在提交前持久登记主体、请求身份和参数摘要，向执行端传递同一操作身份并支持按其查找、补记底层任务关联；同主体同请求同参数重试返回原操作，参数不同明确冲突。提交响应丢失或服务重启时先核对底层操作，无法判定时返回待核对/中断，不自动重发有副作用的分析；不要求恢复任意底层任务，也不依赖长期 `durable-task-lifecycle` Feature。
- MCP 数据工具、F2 产物工具及 F3 Apps 资源使用同一服务的显式模块注册和主体传递；F2/F3 负责各自适配内容，未部署模块不暴露可用工具，F1 可独立运行。不建设动态第三方插件市场或第二套接入服务。
- 控制面走 HTTP，批量计算沿既有数据面；MCP 只返回有界结果或引用，不搬运完整报文/大表。

### 冻结的有限分析与 DNS 数值口径

有限分析使用部署方批准的固定方案；方案选择真实声明且支持块处理/取消的算子，参数、精确配置引用及主体独占派生目标一起冻结。
客户端通过方案引用与来源引用预检/提交，不能覆盖参数或写出目标；解析出的全部数据输入和配置须另获 analyze 授权。
结果清单记录实际 Scheduler 身份、查询、契约执行引用及真实公开关系，数据通过相同查询/分页契约读取。
普通业务统计仍使用结构化 workflow；未证明计算前范围约束的带行过滤来源不进入算子路径。

DNS 固定夹具复用双族 8 种事务（重试、缺响应、孤立响应、TC 截断、未支持报文、捕获截断、时间倒退、TCP）。
按一个实际 run_id 的 final 公开关系计算，每族总数 8；matched=3、query_only=2、其余三种状态各 1。
有效时延定义为 outcome=matched 且 latency_ns 非 NULL 且 response_tc=0；分母 2，mean/min/max 均 10,000,000 ns，容差 1e-6 ns。
RCODE 分布 3→1、0→4、NULL→3；时延分布在相同有效条件下只含 10,000,000 ns→2。
时间桶采用 query_at_ns 的两箱等宽直方图，排除 NULL，范围 [族起点, 族起点+113,000,000] ns，末箱右端闭合；
边界为起点、起点+56,500,000、起点+113,000,000，计数 3 和 4，缺少 query_at_ns 的 1 条单独计入 NULL。
每族另断言方向、截断原因、负时间差置 NULL、revision=1/is_final=1，并对照 history/latest/final 的实际实体身份去重。
这些公式由服务端计算并有独立数值断言，MCP/模型不补算指标。

### 各类通道的接口覆盖与本期交付

以下区分底层通道类型、载荷及本期对外能力。统一描述可以表达有限性、快照、回放/消费和角色差异；
只有已实现并验收的操作才能声明可用。已配置且获准的对象均纳入目录，未加载的 provider 明确不可用，不伪造实例。

| 通道/资源 | 本期必须可发现和描述 | 本期开放的数据操作与边界 |
| --- | --- | --- |
| Database | SQLite/MySQL/PostgreSQL/ClickHouse 的表、授权视图、真实结构与说明 | 有界查询和受管分析输入；保留各库语义，每种声明后端真实验收 |
| DataFrame（含 CSV 导入、内存结果） | 实际对象、结构及快照能力，描述不触发延迟加载 | 显式取得快照后查询/分析；保留来源与快照依据 |
| `IStreamChannel` 结构化流（含已暴露的 Hub） | 实例、Schema 或动态/未知状态、有限性和已有能力 | 本期仅发现/描述；不直接轮询共享队列或建立无限订阅，已产出的 DataFrame/数据库结果按对应能力读取 |
| `IBlockStreamChannel`：PCAP/PCAPNG 文件 | 已注册的文件通道、报文形态、有限性及适用算子 | 单独授权的有限分析，经受管任务产出结构化结果；不以报文通道冒充业务表，不接受任意文件路径 |
| `IBlockStreamChannel`：Kafka、NetAdapter | Kafka 的 structured/packet 载荷与 source/sink/both 角色，NetAdapter 的持续采集属性及可公开元数据 | 本期仅发现/描述；不消费 Kafka、提交位点、启动网卡采集或向 sink 发布；已有落地结果可按其自身能力查询 |
| Config 资源 | 名称、格式、Schema 身份及精确修订引用；独立于 SQL 通道注册表 | 作为获准算子的配置依赖由执行端解析精确修订；本期不开放正文下载或修改，不作为 FROM 表 |

- 核查依据：[四类通道](../../src/framework/interfaces/ichannel.h)、[流能力](../../src/framework/interfaces/istream_channel.h)、[数据集描述](../../src/framework/interfaces/ichannel_dataset_descriptor.h)、[块流类型描述](../../src/framework/interfaces/iblock_stream_channel_descriptor.h)及 [Config 注册接口](../../src/framework/interfaces/iconfig_channel_registry.h)；现有能力发现与入口见 [SQL 工作流](../../docs/sql-workflow.md)。
- Kafka 的结构化载荷仍走块流接口，Config 不属于四类 `IChannel`；公共描述分别记录资源类别、适用的通道类型与数据形态，不根据名称猜测执行路径。
- 目录和能力来自 FlowSQL 的注册/描述接口；所需补齐放在对应通用能力层，MCP 不依赖具体插件类，不硬编码 NPM 表清单或维护第二份字典。
- 同一发现/描述契约覆盖 source、sink 和 Config；只有满足角色、能力与授权的对象可用于请求，不能把 sink 当查询来源或把配置元数据可见等同于内容使用授权。
- 增加一种 provider 时，适配其 FlowSQL 描述与执行能力即可复用 MCP 工具；本期用不同通道及非 NPM 数据验证此边界，不建设额外的通用插件框架。

### MCP 技术方向与独立性

- 优先采用 Python 官方 MCP SDK 实现协议适配层；服务独立性和通道通用契约是固定要求，语言与 SDK 在 T1 最小验证后冻结。只交付一种实现，不要求多语言并行实现或全面选型比较。
- T1 先冻结候选接口和数据契约，再以真实 MCP 客户端、独立 Python 进程验证工具发现、HTTP 调用、有界结果、认证委托及超时/取消映射，并核对干净环境安装和仓库外启动。尚未交付的受控 HTTP 能力可用契约 fixture 验证适配行为，明确记录模拟边界；真实 FlowSQL 的授权、底层取消和完整数据闭环仍由 T4 验收。
- MCP 可单独部署和启停；依赖已运行的 FlowSQL HTTP 服务，不依赖诊断 Agent、Skills、模型凭证或前端。部署配置指定上游地址与认证，支持 MCP 与 FlowSQL 分机运行。
- 若采用 Python，交付独立 Python 包、`pyproject.toml`、明确的依赖约束及启动入口；在干净虚拟环境安装后从仓库外启动，不依赖源码相对路径、`sys.path` 注入或本地 C++ 构建产物。
- Python 包不导入 Scheduler、现有 Python Worker、NPM 或诊断 Agent 的内部模块，不直连数据库/Kafka，不挂载 FlowSQL 数据目录，也不加载 FlowSQL `.so` 插件；按需执行 Python 算子仍由 FlowSQL 正常调度其 Worker。
- 拥有独立配置、监听地址、服务凭证、健康/就绪检查、日志和资源预算；重启 MCP 不重启 FlowSQL/Worker，也不丢失底层任务归属，可按原身份和权限重读状态；上游不可用必须返回明确错误。
- FlowSQL 持有任务、预算、取消和结果寿命；MCP 断连或进程退出不代表任务已取消，底层预算仍有效。传输取消与业务任务取消的映射在 T1 冻结，不能仅中断代理 HTTP 等待就报告已停止。
- 单元/契约测试可用 HTTP fixture 独立运行；集成验收使用独立 MCP 进程和真实 FlowSQL。至少交付独立包/进程方式；若另外声明容器交付，再验收对应镜像与运行契约。
- Python 方案明确为框架外接入服务，与 Worker 职责分开，实施时同步架构说明；如最小验证暴露明确阻塞，再据证据评估其他语言。若最终采用 C++，MCP 能力仍由统一框架加载 `.so`，在独立框架进程运行并满足同等服务边界。

## 主链路

1. **只读调查**：普通 HTTP/MCP 客户端验证访问范围 → 发现通道及实际能力 → 读取对象/字段说明 → 对支持查询的表或快照提交有界查询 → 读取结果与依据 → 可交由 F2 保存；不支持查询的通道明确拒绝。
2. **有限分析**：客户端发现来源及获准算子 → 明确目标、参数/配置修订与受管输出 → 按需预检 → FlowSQL 提交既有有限任务 → 核对状态/取消 → 读取实际结果；MCP 不承载原始数据处理，失败保留阶段和关联任务。
