# Feature: 测试环境可重复执行与预防约束

标识：`test-environment`；优先级：P1；状态：`[x]` T1～T4 已按顺序验收。

## 业务意图

面向本地开发、WSL/Docker 和后续 Feature 的数据库及 Kafka 回归，建立持续可复用的依赖准备与执行契约，
预防配置分散、手工准备遗漏、运行位置与网络地址错配，以及环境失败被误计为测试通过。
从新终端执行标准入口即可获得一致配置和可验证的测试环境；不可用时在业务测试前有界失败并明确归因。
交付既包含工具与隔离夹具，也包含未来新增测试必须遵循的接入规则，不以修复某次历史环境作为完成目标。

## Non-Goals

- 不修改生产数据库/Kafka 接口、SQL、业务认证方式或部署配置，不管理用户的数据库账号与数据、Kafka 集群/Topic/ACL。
- 不自动修改 WSL/Windows 配置、系统路由、防火墙或 Docker daemon，不以固定容器 IP 作为连接契约。
- 不自动删除或重置用户容器、目录、数据卷；测试夹具的破坏性重置必须显式确认。
- 不建立通用容器平台或秘密管理服务；首期夹具覆盖 MySQL、PostgreSQL、ClickHouse、Kafka 及认证所需 KDC/HTTPS 身份服务，SQLite 复用本地测试。
- 不实现 Kafka 四类数据适配器或新增产品认证能力；复用现有真实认证夹具，未来数据面用例按同一契约接入。
- 不把全部采集/特权/其他服务测试迁入 Docker；各测试保留必要运行条件，统一数据库/Kafka 依赖准备与结果汇总。
- 不保证外部环境永不故障；保证可重复准备、及时识别、准确失败和可核查的实际覆盖，不用延长超时掩盖问题。

## 核心契约

### 统一配置与依赖声明

配置在运行时读取，测试公共辅助代码只用于测试，不增加生产 ABI。首期采用版本化 JSON，
仓库示例定义测试专用身份和库角色，私有状态由入口初始化并复用；不要求每次手工 export 或重新运行 CMake。

| 数据 | 必需内容与约束 |
| --- | --- |
| `TestEnvironmentConfigV1` | `schema_version=1`、测试项目身份、数据库与 Kafka 服务配置、运行位置地址映射、身份/凭证引用和资源角色；拒绝缺失必需项、重复定义和未知字段。 |
| `BackendConfigV1` | 原生端点为已发布的宿主机地址/端口；Docker 端点为服务名/内部端口；初始化参数从同一配置派生，预检与用例共用测试身份和库角色，不另设默认密码或固定地址。 |
| `KafkaConfigV1` | 按执行位置映射 bootstrap 与 advertised broker 地址、安全协议/SASL 机制、TLS 与身份凭证引用、Topic/组/ACL 角色、KDC 或 HTTPS token/JWKS 端点和对应信任配置；管理身份与用例身份分开。 |
| `CredentialBindingV1` | 入口生成的测试专用秘密，或显式环境/私有文件引用；覆盖数据库密码、SASL 密码、TLS 私钥、keytab、OAuth client_secret/token；私有文件仅所属用户可读写，不进 Git，日志、命令行及汇总不含秘密或秘密摘要。 |
| `DatabaseRolesV1` | 显式映射各套件所需源库/目标库，初始化负责建库和授予必要权限；不同套件保持需要的隔离，不假定服务启动即已建库。 |
| `TestDependencyV1` | 每个用例声明数据库后端/库角色或 Kafka 协议/认证 profile、身份服务、Topic/组/ACL 操作、执行位置与共享资源；真实认证脚本也纳入统一清单和 CTest，声明作为选择、预检和锁定的同一来源。 |
| `TestRunSummaryV1` | `run_id`、所选配置的非秘密版本信息、执行位置、后端与阶段、错误类别、选中/执行/通过/失败/跳过/未执行数及用例名单；不得将跳过和未执行计入通过。 |

受管夹具与显式外部端点分开：默认使用独立测试项目；外部模式须声明专用测试库或 Kafka 测试资源，禁止对用户业务库/Topic/组/ACL 执行初始化或清理。
旧的 `MYSQL_* / PG_* / CH_*` 拼接、NPM 写死连接和 Baseliner 临时 options 路径统一接入新配置；
如现有内部调用需要 options 字符串或文件，由测试辅助代码从同一配置派生，不继续人工维护多份真相。
CMake 只记录测试依赖和执行要求，不捕获凭证值或临时配置路径；切换配置无需重新配置或编译。
凭证与已有数据卷的一致性必须经真实认证验证，不能把修改初始化环境变量当作已更新库内密码；不静默重置卷。
有意构造错误密码、地址或权限的负向用例保留独立预期，从有效测试配置派生，不将预期失败当作就绪证据。

### Kafka 依赖与验证边界

首期统一接入现有 [Kafka 认证说明](../../docs/kafka.md) 和真实认证夹具，不另建第二套认证实现。
配置覆盖 PLAINTEXT、SSL、SASL_PLAINTEXT、SASL_SSL，TLS 服务端/mTLS、PLAIN、双 SCRAM、GSSAPI 和 OAUTHBEARER。
bootstrap 可达后，仍须从实际客户端位置验证元数据返回的 broker 地址；受管 advertised.listeners 与原生/Docker 地址映射同源生成。
Broker、KDC、HTTPS token/JWKS 服务使用同一隔离网络；TLS 主机名/SAN、CA、Kerberos service principal 与服务地址一致，
不能通过关闭证书校验、降级协议或把 WSL localhost 当作 Docker host 网络来绕过连接问题。
夹具声明并检查 JRE、openssl、Python cryptography、MIT KDC 工具，以及客户端运行库、SASL GSSAPI 插件、kinit 和 CA；
缓存校验的 Kafka 发行包与测试镜像可复用，缺失或版本不匹配明确失败，不依赖某个历史 evidence 目录才能运行。

受管 fixture 幂等准备测试账号、证书、principal/keytab、签名 token 服务与具名 Topic/ACL；资源按测试项目/运行身份隔离，
消费组、Topic、票据缓存和身份秘密不得与用户资源或并行测试串用；失败/取消释放本轮进程、客户端和私有缓存。
认证矩阵中需要的长驻留续期/刷新属于用例执行预算，独立于环境准备预算；缩短等待不能使续期覆盖消失。
doctor 与常规连接预检仅进行网络、TLS/SASL、身份服务和元数据检查，不创建 Topic、不发布、不订阅、不消费、不提交位点；
元数据成功后仍报告读写权限未验证。测试资源创建由独立 fixture 准备阶段执行，不能由 Probe 自动创建掩盖缺失 Topic。
未来数据面用例须声明 source/sink 所需 Topic/组及读写 ACL，仅在隔离资源上验证实际操作，不能以元数据成功替代权限与数据链路验收。

### 隔离夹具与运行入口

数据库/Kafka 集成测试默认在同一 Docker 内网使用服务名；受管服务使用独立项目、网络和卷，镜像版本与摘要固定。
测试执行镜像复用当前构建产物和共享第三方缓存，检查必需运行库、插件与工作目录，不每轮重编第三方。
复用环境须核对配置及镜像版本并重新预检；首次初始化幂等，失败不能借用名称相同的用户容器冒充测试夹具。
原生数据库调试模式显式选择宿主机发布端点；仅可使用配置声明且预检成功的地址，不尝试猜测私网 IP。

已交付的 CLI 契约：

| 入口 | 可观察行为 |
| --- | --- |
| `tools/test.sh unit` | 执行不依赖外部服务的注册用例，无需启动数据库、Kafka、身份服务或 Docker；本地 socket/特权仍须满足自身执行要求。 |
| `tools/test.sh doctor` | 只读核验所选执行位置、配置、访问权限、现有服务、认证、库和可检查的授权；不建库、不写数据、不改环境。 |
| `tools/test.sh integration` | 按所选用例准备数据库/Kafka 与必要身份服务并从实际环境预检，执行对应真实依赖用例；默认 Docker，显式支持原生调试。 |
| `tools/test.sh all` | 将全部注册用例按依赖和执行位置分配并汇总，每个选中用例恰好一次；其他夹具沿用自身准备要求，不能漏测后声称完整回归。 |

入口支持显式配置与测试筛选；`all` 的最终完整验收不筛除必需用例。已有 CMake 构建入口保持不变。
`ctest` 按声明挂接 fixture 和资源锁，从当前执行环境校验必要依赖；直接运行集成用例也必须明确失败或执行预检，
不能因绕过外层脚本恢复旧的静默跳过行为。共享表/库采用声明的资源锁，互不干扰的用例可并行。
未注册的数据库驱动/通道用例和 Kafka 真实认证/部署脚本纳入 CTest 清单；混合套件分开本地与外部依赖部分，unit 不隐式连接数据库或 Kafka。
Kafka 现有普通 CTest、真实客户端/HTTP 认证矩阵及原生/Docker 部署回归分别列明，禁止只运行普通 CTest 后声称真实认证全覆盖。
运行状态与临时配置由工具管理；每次验收的日志、结果摘要与源码/二进制摘要保存在 `evidence/test-environment/`，不入库。

### 预检与失败语义

预检依次检查配置、执行权限、必需产物、服务状态、实际端点连接与真实认证，按声明检查数据库/权限或 Kafka 元数据与身份依赖。
healthy、TCP 可连接、容器内查询成功均不能替代测试执行位置的认证查询。
集成入口可在专用测试库中建表/读写/清理以验证操作权限；doctor 只读检查，无法证明的权限明确为未验证。

错误类别至少包括：`config_missing / config_invalid / execution_denied / artifact_missing / service_unavailable`、
`network_unreachable / authentication_failed / database_missing / permission_denied / preparation_timeout / test_failed`。
Kafka 额外区分 `broker_address_unreachable / tls_validation_failed / mechanism_unavailable / topic_missing / metadata_denied`、
`kerberos_unavailable / token_service_unavailable / credential_expired`；续期/刷新失败不得归类为已通过的初次认证。
输出后端、端点、失败阶段和可操作原因，原始驱动错误须脱敏；业务错误与环境准备失败分别报告。
瞬时启动失败允许有界重试；认证、配置或明确权限错误立即失败。配置中声明准备总预算和单次连接预算，
默认总预算 60 秒、单次连接最多 3 秒，不随用例数量线性累加；到期终止准备并返回非零。
本轮预检成功后冻结配置；后续真实连接或操作失败仍返回非零，不认为预检成功保证环境永远有效。
正式集成和完整验收要求选中用例全部实际执行、零环境跳过；纯单测入口的明确排除不计入完整验收。
现有测试中“打印 SKIP 后返回 0”的行为必须消除，所需依赖不可用不得降级成通过或仅验证连接失败。

## 主链路

1. 执行者调用标准入口 → 加载统一配置与测试依赖声明 → 核对运行产物 → 幂等准备所需数据库/Kafka/身份服务夹具
   → 从实际执行位置完成认证与权限预检 → 冻结本轮配置并执行对应 CTest → 汇总全部结果与证据。
2. 后续 Feature 新增/修改依赖测试 → 同切片更新声明与共享资源 → 接入公共配置和 fixture
   → 在新终端及故障注入下验证准备/失败行为 → 通过标准入口验收，报告实际覆盖和环境限制。

## 项目规则与接入约束

[AGENTS.md](../../AGENTS.md) 的“测试依赖与可重复执行”规则即时约束后续任务：
冻结切片时明确测试依赖、执行位置与配置来源，运行前核验真实认证，不使用临时网络修改或静默跳过完成验收。
工具交付前按实际已有入口完成并记录等价预检；工具交付后使用标准入口，禁止引用未实现命令为已可用能力。
使用步骤在交付时集中维护一篇测试说明，README 引用；具体命令、配置与故障示例放说明，通用约束留在项目规则。
规则不复制到 lessons，也不积累某次端口、临时目录、容器 IP 或历史路由修复命令。

## Feature 验收矩阵

| 场景 | 必须证明的结果 |
| --- | --- |
| 新终端、无人工 export、空测试状态 | 标准入口准备数据库及 Kafka/身份依赖，执行全部所需真实服务测试。 |
| 相同配置连续三次执行、并行执行 | 环境可复用，无测试表、Topic/组、身份缓存或临时文件串扰，运行摘要与选中清单一致。 |
| 配置或凭证引用缺失、密码错误、测试库缺失、权限不足 | 对应错误分类和非零退出；业务用例未执行；达到预算即停止，无秘密泄露。 |
| Docker/socket 或本地 socket 权限不足 | 识别执行限制，不误报密码错误，不通过跳过、替代路径或放宽断言完成验收。 |
| 宿主机发布端口不可用、容器服务名可达 | 默认 Docker 模式仍执行真实数据库测试；显式原生模式准确报告网络失败。 |
| 修改配置、复用已有卷或中断后重试 | 无需重编，初始化幂等；凭证不匹配明确失败，用户资源与数据保持。 |
| 新增依赖测试、直接 CTest、完整回归 | 声明被执行选择和 fixture 使用；缺依赖不能静默成功；全量清单无遗漏、重复或环境跳过。 |
| Kafka bootstrap 可达但 advertised broker 不可达 | 从实际客户端位置识别返回地址错误，不能因 bootstrap/TCP 成功标记就绪。 |
| Kafka 证书/主机名、密码/机制、KDC/OIDC 错误或 Topic 不存在 | 对应阶段明确失败、秘密不泄露，不降级协议、不关闭校验、不自动创建缺失 Topic。 |
| Kafka 完整认证与生命周期回归 | 原生/Docker 覆盖四协议、mTLS、PLAIN、双 SCRAM、双身份 GSSAPI 隔离/续期、签名 HTTPS OAuth/刷新及失败路径；真实客户端/HTTP 和部署回归均执行。 |
| Kafka metadata-only 与未来数据测试 | 常规预检不改变 Topic、消息、组或位点，读写权限未验证；未来数据用例只在隔离资源上按声明证明数据操作。 |

网络故障注入限定于独立测试夹具，不修改宿主机路由或用户服务；受环境限制的用例须报告未验证，不能勾选完成。
