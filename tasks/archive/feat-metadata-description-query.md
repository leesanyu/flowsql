# Feature：通道与算子说明管理（metadata-description-query）

状态：`[x]` 已完成并归档；优先级：P1；完成日期：2026-10-30。
沿用原 Feature 标识，替代原“通道字典与算子契约查询”规格；T1～T5 按本次边界重新定义，已按顺序逐项验收和标记。
依赖已完成的 [标准与字典管理](../archive/feat-data-semantics-registry.md)、[通道数据字典生成与绑定](../archive/feat-channel-data-dictionary.md)、[算子输入输出契约](../archive/feat-operator-data-contract.md)。
本 Feature 是 [数据说明与算子调用基础 Epic](../specs/epic-data-semantics-dictionary.md) 的对象入口与 HTTP 交付，排在 F3 后、NPM 说明与模型诊断前。

## 业务意图与 Non-Goals

让使用者在具体通道实例上看懂并补充数据说明，在具体算子上查看和维护调用说明与契约；未来大模型通过相同 HTTP 接口发现对象、理解数据并选择正确的调用方式。
用户的正常路径是“打开对象 → 查看结构与说明 → 补充必要内容 → 保存”，无需先创建标准、命名字典、建立绑定或填写内部身份。
本轮目标是可调用、可理解的对象说明；不建设独立标准数据字典产品。

- 不新增标准库、治理审批、全库扫描或共享字典编排；已有存储、精确版本、绑定与历史能力作为内部基础复用。
- 不调用大模型、不实现 MCP/function calling 适配或诊断 Agent；以普通 HTTP 客户端证明模型将来需要的发现/描述/预检/执行路径可用。
- 不推测字段单位或业务含义，不运行数据质量校验，不自动改变字段类型、算法、单位或执行参数。
- 不默认读取业务行、加载 CSV、消费 Kafka 或运行算子；显式加载和预检保持独立用户操作。
- 不改执行 ABI/虚表、批/流任务生命周期或已有执行前契约检查，不重建 provider/元数据存储体系，不删除或迁移既有定义。
- 前端调整限于本 Feature 入口及受其影响的列表/详情布局恢复，不重设计全站表格或改变既有管理操作的业务语义。
- SQL 工作台 DESC、查询结果/图表就地说明和通用引用浏览归入后续 [F5](../specs/epic-data-semantics-dictionary.md#data-semantics-consumption)，不作为本 Feature 或模型接入的前置门槛。

## 用户入口与交付边界

| 入口 | 本 Feature 交付 |
| --- | --- |
| 顶栏 | 移除“标准与字典”常规导航；已有接口与历史文档链接可继续访问，旧管理页只作兼容入口，不作为新流程的必经步骤 |
| 通道列表/详情 | 通过对象名称或已有详情进入“数据说明”；系统带出结构，允许编辑含义并点击一次“保存说明”，列表不继续堆叠字典/绑定按钮 |
| 数据库连接 | 在已有“浏览”入口选择明确 database/schema/table，再查看和维护表说明；两段式连接只作连接/表目录入口，不建立字段字典，也不提示缺少字典 |
| 算子列表/详情 | 在已有查看/编辑详情中展示“说明与契约”，包含用途、输入、参数、输出、示例和限制；提供补充说明编辑及适用的声明维护入口 |
| 程序调用 | 复用现有通道/算子目录，按对象调用统一描述接口；结果包含结构化说明、来源、当前关联版本和未知状态 |

- 结构化 DataFrame/CSV、Kafka source/both、已支持四库限定表沿用 F2。packet、sink-only、配置等其他通道显示基础身份与 unsupported 原因，不扩展字段描述能力。
- 从页面进入时无需用户输入字典名、binding_ref、provider_id/object_id 或 field_map；内部引用只在“技术详情”中按需展示。
- 标准引用不是填写说明的前提；没有说明也展示已知结构。默认只呈现有用字段及简明缺失提示，不把每个可选未知属性都列为待修复错误。
- 全部对象入口使用同一读取内容与保存规则；长字段表可筛选/折叠，原始 JSON 可复制，不引入第二份“给模型的说明”。

### 入口替换与表格显示恢复

现有通道入口曾在原固定/最小宽度的操作列中追加“数据字典／表字典”按钮，未配套处理布局；现有浏览器流程也未验证按钮的实际可见性与遮挡。
本 Feature 必须同时完成入口迁移和受影响表格的显示修复，不能仅删除顶栏菜单或替换按钮文案。算子列表未因 F3 新增列，保留其已有布局，以详情面板隔离契约内容。

| 当前入口 | 替换结果与必须保留的能力 |
| --- | --- |
| DataFrame/CSV 行内“数据字典” | 移入名称打开的对象详情“数据说明”；保留行内预览、重命名、删除，恢复不含新增字典按钮的操作布局；预览仍为明确读取数据的动作 |
| 数据库行内“表字典”及手填表名弹窗 | 移除这条重复常规路径；保留浏览、删除，从浏览中的表目录选择表后打开“数据说明”，不要求先创建连接级字典 |
| Kafka 行内“数据字典” | 收入已有详情的“数据说明”；保留详情、编辑、验证、复制引用、删除和原禁用规则；连接配置、packet、sink-only 不出现可编辑字段字典 |
| Python/内置/C++ 算子详情 | 在详情内分组展示说明、契约、源码或插件信息；保留新建/上传、查看/编辑、激活/去激活、删除和插件更新；C++ 仍须选定具体算子，不把插件视作单一契约 |
| “标准与字典”导航与旧链接 | 移除常规导航和对象页到旧通用编辑器的跳转；保留旧路由、精确引用、接口及历史数据，兼容访问不在列表中留下空白列或占位按钮 |

- 列表保持名称、类型、状态、结构摘要等既有信息；字典状态、绑定引用、长 JSON 和字段编辑表放在详情，不新增常驻元数据列，不扩大操作列来容纳已迁出的入口。
- 清理仅为旧入口保留的空间、事件和局部样式；新面板样式限于自身，不能影响其他列表、数据预览、SQL 结果表或兼容页面。
- 长名称/类型/说明可截断并查看完整内容；表头与数据列对齐，按钮不重叠、不被裁切、不出现意外折行撑高；宽表允许在自身容器内横向滚动，不撑宽整个页面，滚动后操作可见且可点击。
- 详情关闭后保留列表筛选、选中类别及已有滚动位置；切换对象/表时刷新对应说明，不将上一对象的字段或草稿混入下一对象。
- 打开列表不逐行加载说明。DataFrame 详情不借道预览隐式加载；数据库打开浏览、选表、查看结构/说明只读元数据，业务行只在用户选择“数据预览”后请求。当前选表同时预取业务行的路径须拆开，并保留显式预览及分页能力。

## 核心契约

### 对象描述：结构与说明分别表达

新增同步 `POST /api/semantics/v1/describe`，部署内路径 `/semantics/v1/describe`，沿用 Web/Gateway 与 Config 语义控制路由。
请求按明确对象定位，不接收任意业务 SQL；以下为完整请求示例：

```json
{"target":{"kind":"channel","locator":{"kind":"dataframe","name":"VNAT"}},"timeout_ms":5000}
```

```json
{"target":{"kind":"operator","name":"explore.chisquare"},"timeout_ms":5000}
```

| `MetadataDescription`（成功信封为 `{data:...}`） | 必需含义 |
| --- | --- |
| `subject`、`basis` | 规范定位和实际身份；通道的 object_key/source_revision、算子的 component_revision，以及本次捕获的精确引用；保存时原样回传作并发依据 |
| `structure` | 当前可得结构及 `known/pending/unsupported`；字段完整类型/可空性、原始来源和观察时间，不被人工说明替代 |
| `description` | 对象说明及 `present/missing/needs_review`；来源可以是作者声明或人工补充，保留未知属性；未保存说明不妨碍返回已知结构 |
| `contract` | 算子静态输入/参数/输出/限制及 `declared/missing`，采用 F3 原模型；不把补充说明冒充执行契约 |
| `checks`、`gaps` | 复用 F2 匹配状态和缺口，区分结构未就绪、未填写说明、结构变化；`data_validation=not_run`，未显式预检不返回 compatible |
| `context` | 解释字段/结果所必需的行粒度、时间、NULL、有效性、关联、修订/聚合及精确上下文引用；不自动递归展开整个引用图 |

- 现有 F1/F2/F3 文档、locator、类型和 SemanticValue 是事实来源；上表是对象读取视图，不新建一套字典/契约模型。
- 描述器先捕获对象/组件关联，再读取精确文档；不得以定义库最新版本替代当前对象版本，不把并发替换前后的结构与说明拼接成 matched。
- 未加载 DataFrame 返回结构 pending；已有保存说明可带“未核对当前结构”标识展示。打开页面或目录查询不隐式加载；用户显式加载后再刷新。
- 来源结构已知但没有绑定，返回字段、说明 missing 及内部 unbound；不返回让人误判为“没有字段”的全空视图，也不为读取创建字典/绑定。
- 不存在返回 404；已声明引用丢失、来源不可用、认证失败与超时返回现有结构化错误，不降级为 missing；冲突返回 409，失效后清除旧 matched。
- 复用既有 `{error:{code,message,field_path,details}}`；读取默认总预算 5000ms，各子调用共享剩余预算，耗尽返回 504；不无限重试。
- 字段裁剪/体积限制沿用 F1，保留必要上下文与完整性标记；原始凭证和业务行不进入响应。

### 通道说明：一次保存，身份和关联由系统处理

系统根据 F2 的真实结构生成编辑表单，默认仅开放对象说明、一行含义、字段说明、单位、枚举/NULL 含义；时间、关联和聚合等作为可展开的必要补充。
名称、类型、可空性只读；保留现有完整语义中未被本次编辑的部分，不以简化表单覆盖或清空它们。
结构 pending 时可查看已保存说明，字段配置待结构就绪后开放，不允许用不完整结构应用绑定。
新增 `POST /api/semantics/v1/channels/save-description`，部署内同前缀，核心模型如下：

| 模型 | 内容 |
| --- | --- |
| `ChannelDescriptionSave` | F2 locator、describe 返回的 basis、限定可编辑属性的 changes；按来源字段关联说明，不接受客户端修改内部身份/结构或指定任意绑定 |
| `DescriptionSaveResult` | `status=applied|definition_saved_not_applied`、已保存定义与已应用绑定的精确引用、更新后的依据及错误/需确认项 |

- 默认编辑作用域为当前对象；若原字典被其他对象共用，创建当前对象使用的修订/副本并只更新当前绑定，不能静默改变其他通道说明。
- 生成内部名称、保留字段身份、字段映射及版本均由系统处理；以本次来源与已读版本校验保存/应用。结构变化保留原稿并提示差异，删除/重命名不能静默猜测。
- 复用 F1 保存与 F2 apply 的核对/持久化，不承诺把已有两个事务变成跨服务事务；字典已保存但应用失败必须如实返回部分成功，页面保留输入和已保存引用，不显示“保存完成”。
- 同名对象替换、字段重建或来源语义连续性需确认时，说明具体变化并让用户确认；内部适配不得自动勾选 F2 required_confirmations。
- 必须以 basis 检测过期提交，不用盲目覆盖解决冲突；重试读取已保存依据，避免相同提交无意义地产生重复修订。

### 算子说明：补充文字与可执行声明各有来源

按算子展示用途/适用条件、输入角色及 selector、参数必填项/默认值/约束、输出实体、调用示例和局限；默认以表格和分组阅读，JSON 收入技术详情。
explore.chisquare 验证普通算子；explore.baseliner 保留嵌套配置与 results/model_parameters/relation_fusion/maintenance 四实体及条件分支，不压成一张字段表。

| 内容 | 配置方式与保证 |
| --- | --- |
| 用途、使用注意、调用示例 | 在当前算子中直接编辑“补充说明”；描述接口同时标明组件作者声明和本地补充，不覆盖原契约字段 |
| Python 执行契约 | 在算子详情进入已有源码/静态声明编辑流程，保留组件版本冲突检查，声明随注册/上传更新；不另建绕过组件身份的在线契约覆盖 |
| C++ 执行契约 | 展示随当前插件发布的声明，并从该算子进入所属插件的更新流程；不能把页面编辑解释成二进制算法能力已经改变 |
| 预检参数 | 仍是本次预检/调用的输入，默认不写回算子全局参数；明确点击后才走已有检查入口 |

新增 `POST /api/semantics/v1/operators/save-description`，请求为 `name`、`expected_component_revision`、`expected_description_ref` 与 `notes`。
notes 仅含 `purpose`、`usage_notes`、`examples`，JSON 结构在 T1 冻结；保存至现有 Config 版本资源，按 `(category,name,component_revision)` 关联，返回精确 description_ref。
这份资源只承载可编辑补充说明，不复制执行契约或另建数据库；无补充也能完整读取作者契约。
组件更换后旧说明保留为旧组件依据，不能静默套用到新版本；可显式复制核对后保存。保存补充说明不改变契约检查、算法参数或已有任务快照。

### 兼容与模型调用边界

- 保留 F1/F2/F3 既有读取、版本与保存接口，不删除现有定义；移除主导航后，旧 `/semantics` 链接仍可读取已有内容，对象内编辑不再依赖通用新建表单。
- C++ 服务依旧经 IID/IQuerier 访问本进程能力、跨服务用 HTTP；新增能力先冻结独立公共类型/IID，不能修改原执行虚表或直接依赖具体 Plugin。
- 发布 describe/保存接口的 JSON Schema Draft 2020-12 与 OpenAPI 3.1；普通脚本复用现有目录完成发现→描述→显式预检→已有 SQL 执行→结果引用读取。
- 描述/目录请求不创建任务、不执行算法；模型接入方将来执行任务仍必须使用既有执行入口与约束，说明文本不成为服务端自动执行指令。
- 技术详情可以读取已有精确历史版本；首期不建设通用历史搜索、引用关系图或完整导入导出工作台。

## 两条主链路

1. 通道实例→只读取得结构/说明→用户补充→保存说明→重核对象/结构及版本→保存定义并应用当前对象→刷新；说明缺失仍可读结构，结构冲突保留原稿。
2. 算子对象→读取作者契约和当前组件补充说明→用户编辑并保存补充，或进入适用的组件声明更新流程→按组件版本重读；Web 与普通 HTTP 读取一致，读取与执行分离。
