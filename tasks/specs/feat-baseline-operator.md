# Baseline 封装算子

## 业务意图

让 FlowSQL 中以 Value、Ratio、Relation 持续检测上游数据的用户，获得类型化的观测接入与结果输出，并在某个 series/source 停止到达数据时仍能按显式策略回收状态；将接入、活动、容量策略与时间驱动放在算子层，使通用算法插件保持被动调用且资源可管理。

状态：后续待办，未开始；来源：[baseline 检视修复](../archive/feat-baseline-review-fixes.md) B06 封装算子部分。插件状态控制能力完成并验收是实施依赖；本规格登记后续交付，未冻结算子公开数据 Schema。

## Non-Goals

不在 baseline 算法插件内接入 Scheduler/具体产品、创建定时器或后台线程，不修改检测算法，不引入并发 task 查询或算法状态 mutex，不默认启用统一 TTL，不实现事件时间水位系统、永久逐身份去重或新的模型持久化平台，不同时开始本规格和原修复任务。

离线回放不使用实际处理耗时判断“不活跃”；业务事件时间过期需依赖有事实依据的上游水位，另行明确需求后规划。本 Feature 首先交付显式启用的在线不活跃策略。

## 依赖与责任

- 插件 T4 提供三类任务的可选容量约束、RuntimeOnly/AllState 释放、实际内部清理与 usage 查询；缺少所需能力时算子 Open 明确失败，不降级为无界运行。
- 复用现有 C++ 算子插件、IQuerier、Arrow block 与 IBlockTransformTaskV2；通过 GetTimeDriveState/OnTime 与 ProcessBlock/Flush 串行协作，不更改框架线程模型。
- 算子拥有调用顺序、输入身份、活动/截止时间索引、淘汰选择、重入水位及恢复策略；插件拥有内部容器及实际释放，不由算子了解/直接操作具体实现类。

## 核心数据契约（在 T1 冻结）

| 数据 | 本次明确边界 | T1 必须交付 |
|---|---|---|
| 观测输入 | 稳定 series/source 身份、bucket 和 kind 所需的值/分子分母/Relation group 与 metric；输入转为既有算法类型。 | 算子 ID、参数入口、三类输入 Arrow Schema、字段映射、空值/非法观测和顺序规则。 |
| 检测输出 | 沿用算法 status、观测身份/bucket、band/control 与 Relation routed/fusion 的事实，不把回收动作解释成异常告警。 | 拥有型输出 Arrow Schema、检测与维护结果的表示、错误/终结规则及主路径测试。 |
| StatePolicy | 显式有限 runtime/model/历史版本限额；在线 idle_timeout 默认禁用、启用时为正时长；淘汰选择、释放 scope 与重入恢复口径明确。 | 参数类型、单位/范围、capacity 行为以及 seed 恢复/冷启动与水位保证的契约。 |
| ActivityEntry | 只在算法成功消费观测后更新活动；预测、查询、非法/重复提交不续期；以单调处理时间记 deadline，与 bucket 时间分离。 | 有限的身份/截止时间索引结构和维护预算，不保留无限 tombstone。 |

“过期”在本 Feature 中指在线运行下距最近成功消费观测的单调时间超过显式 idle_timeout；由算子 OnTime 或数据处理后的同一维护点判断，baseline 不自行判断。算子的活动、水位与候选淘汰元数据也需随释放删除并受容量约束。

## 主链路

1. Open 冻结 Schema/策略并取得服务及状态控制句柄 → ProcessBlock 转换合法观测并按序 Submit → 发布类型化结果，成功消费后记录活动与最早截止时间；新身份遇满额先按已冻结策略释放目标或明确拒绝，不无限重试。
2. GetTimeDriveState 声明最早维护期限 → 框架在无数据、持续繁忙及背压时串行 OnTime → 在预算内选择到期身份并调用插件释放 → 删除算子对应活动元数据并更新下一期限；ReleaseTask 在所有回调结束后关闭算法任务并释放句柄。

## 线程、锁与维护预算

| 路径 | 明确标识 |
|---|---|
| ProcessBlock/OnTime/Flush/算法管理调用 | **新增维护线程 0，新增算法状态 mutex 0**；同一算子任务串行，跨执行线程有 happens-before，保留框架已有调度同步。 |
| Cancel | **可并发，只使用已有取消机制或原子停止信号**；不调用算法 ReleaseIdentity/Close，不访问活动或算法容器。 |
| ReleaseTask | **等待同任务调用结束后关闭**；库所有者晚于算法句柄、Schema、结果销毁，不因提前卸载插件产生悬空对象。 |
| 外部查询 | 消费已发布结果；不从 HTTP 线程透传调用在线算法任务。本 Feature 不增加共享 task 读写锁。 |
| 维护预算 | 约束候选遍历和实际释放工作；计入 Relation 单 source 的 metric/summary/版本扇出，不能只按释放次数声称固定耗时；到期剩余工作留下一次串行通知。 |

活动索引、截止时间更新与维护遍历属于算子新增结构成本；T1 明确算法和预算，实施时以相同工作负载测量并按用户约定讨论实质影响，不将接口串行推断成无性能成本。若以后需要后台直接维护或并发 task 查询，须另立线程/同步契约，本方案不覆盖。

## Feature Task

- [ ] T1：交付冻结的观测/输出与 StatePolicy 契约，使调用方明确支持的数据、过期依据、容量及重入行为，并以关键测试约束实现。
- [ ] T2：交付三类观测的串行接入与类型化检测结果，使上游 Arrow 数据可经通用算法插件完成检测且错误不污染状态。
- [ ] T3：交付时间驱动的在线不活跃回收与有限容量策略，使停发数据、持续繁忙和背压下仍能维护状态，且重入行为与恢复契约一致。
- [ ] T4：交付完整取消/终结/关闭及回归证据，使同任务管理调用不重叠、无额外维护线程/状态锁，资源账目在生命周期结束后归零。

## 验收

- Value/Ratio/Relation 输入和结果对应；非法/重复观测不续期，满额准入行为与释放 scope 明确，模型和在线额度分别可观察。
- 模拟单调时间验证无数据到达、持续输入和背压时期限维护；默认禁用 TTL、离线回放和不同任务隔离不受实际处理耗时误淘汰。
- 同时核对插件 usage 与算子活动索引数量；RuntimeOnly seed 恢复、AllState 冷启动、迟到旧数据的上游水位约束及释放失败保持。
- 取消信号不访问算法状态；回调顺序记录证明非重叠，全部回调结束后才关闭/卸载；结合扇出测量维护延迟与稳态吞吐。
- 按 Feature 完成条件构建对应 target、运行回归及完整 CTest；当前仅登记规格，尚无实现验收证据。
