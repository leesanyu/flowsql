# Feature：独立部署的专用诊断 Agent（diagnosis-agent）

状态：`[ ]` 规划草案，未实施；优先级 P1；创建日期：2026-11-25；更新日期：2026-11-26。
所属 [诊断 Epic](epic-llm-skill-diagnosis.md)：F4；依赖 [F1](../archive/feat-agent-data-access.md)、[F2](feat-diagnosis-artifacts.md) 及 [F3](feat-diagnosis-skills.md) 的技能包/评测契约；不以 F3 Apps 适配或 F5 工作台完成为前提。

## 业务意图与 Non-Goals

让部署者以独立服务运行针对 FlowSQL 的诊断 Agent，并让程序客户端持续提问、补充信息和取消调查，
获得状态可观察、证据可追溯、重启后可核对和继续的调查结果；产品内置体验不改变独立部署边界。

- 不从零训练大模型，不直接重建通用 Agent 框架，不把框架名或单次演示成功作为选型依据。
- 不实现产品工作台、另一套 Skills/数据工具/报告存储，也不承诺恢复任意底层采集或分析任务。
- 不默认把多个 Agent、任意脚本沙箱或向量库全部纳入；需有声明场景和效果依据。
- 不把自托管 Agent 等同于本地模型，不承诺未经验证的供应商/模型或离线推理能力。

## 核心数据与接口契约

T1 在实现前输出并冻结会话、状态、事件、模型接入和持久化边界；T2 起使用同一契约。

| 数据 | 核心内容与保证 |
| --- | --- |
| `DiagnosisSession` | 主体、问题及 AnalysisContext 修订、消息/请求身份、调查状态、待输入事项、预算、证据/报告引用和当前运行身份 |
| `InvestigationState` | 可公开的事实、候选解释、支持/反证、操作记录和继续条件；不要求读取或保存模型内部思维链，运行时私有检查点不作为用户结论 |
| `DiagnosisEvent` | 会话/运行身份、单调事件序号、消息、工具进度、状态变化、产物引用和错误；提供续读游标及状态快照，事件过期时明确要求重新同步 |
| `ToolOperation` | F1/F2 真实请求/任务身份、参数依据、状态及结果引用；恢复时先核对，不盲目重放副作用 |
| `AgentConfiguration` | 模型提供方、部署地址与凭证引用、技能发布身份、允许能力、时间/调用/费用预算及持久化配置 |

- 提供创建/读取会话、提交消息或用户补充、读取事件、取消及显式继续能力；前端协议优先评估 AG-UI，并在 T1 冻结与业务事件的对应关系。
- 增加按主体列举会话的分页入口，所有读取/提交/取消均校验会话归属；主体与委托沿用 F1，F4 不相信客户端填写的用户身份。继续时重新验证现有权限，权限失效进入待授权，不盲用历史凭证。
- 一个会话同一时刻只有一个调查运行；重复消息按请求身份去重，同身份不同内容冲突，并发补充明确拒绝或进入待输入流程，不启动第二条竞争调查。F2 报告保存使用预期修订，禁止 Agent 覆盖用户已编辑的版本。
- 状态至少区分待运行、调查中、待输入、取消请求中、已完成、已取消、失败和中断待核对；会话完成表示当前调查结束，可带证据缺口，不等同于已确定根因。若选用 AG-UI，按其[事件契约](https://docs.ag-ui.com/concepts/events)适配；持久顺序、重放和业务终态由 F4 保证。
- 调查采用“问题范围→说明→候选解释→获取证据→验证/排除→继续或报告”；模型决定调查步骤，程序执行权限、数值和引用检查。
- 原有授权范围内的普通读操作连续执行；需要新的范围、风险决策或缺失信息时才进入待输入状态，未回答不视为同意。
- 主 Agent 统一负责结论；需要并行假设验证时评估专用子 Agent，使用同一证据引用和资源预算，不直接合并互相矛盾的自由文本。
- Skills 复用 F3；字段、结果、表图和报告只通过 F1/F2 契约取得。模型上下文使用有界结果与引用，不能加载整个数据库。
- 会话与操作状态持久化；F2 已保存证据/报告不因 Agent 重启或停机而失效，未完成操作必须与 F1/F2 实际状态对账。
- 调用 F1/F2 前持久化工具请求身份及参数摘要，重启或响应丢失后按原身份核对；未知操作先标为待核对，不能换新请求身份重跑。F1 临时结果过期时保留缺口，需新查询则作为新的观测；长期证据只引用 F2。
- 断连不等于取消；取消必须核对模型循环及已发起工具操作的真实状态，不能遗留无归属查询或写操作。
- 取消后停止发起新工具，已接收的查询/保存/导出逐项核对；模型调用无法即时中止时丢弃迟到输出并保持真实状态，不提前报告底层已取消。时间、工具次数及模型输出量在调用前执行预算；费用不可精确取得时标明估算与误差，不承诺供应商账单的硬上限。
- 独立进程/容器拥有配置、健康检查、资源限制、持久卷及模型凭证；不加载进 Scheduler，也不与现有 Python Worker 共用生命周期。
- 如采用 Python，明确它是框架外应用服务，C++ 数据能力仍按 `.so`/IID/HTTP 边界运行；实现前同步必要架构说明。
- 最低交付为独立包/进程，至少支持一项实际模型接入；配置声明模型可接收的数据范围及调用预算。使用可持久化的检查点/会话存储并限定保存量，重启恢复测试不能用内存存储替代；首次只要求单实例会话写入，不扩展集群调度。

## 选型与实测边界

- 以报告中的 Deep Agents/LangGraph 为优先候选，与 OpenAI Agents SDK、Pydantic AI 比较同一最小工具、数据及会话/恢复场景；记录 Claude Agent SDK、平台方案、直接模型 API 的取舍。对照限于必要原型，完整产品链路和重复 DNS 评测仅对最终方案执行，不开发三套产品。
- 不预先将当前建议标为最终选择；候选原型使用同一 F3 评测输入，评估诊断质量、状态控制、Skills、MCP、事件、成本和部署负担。
- T1 冻结真实原型矩阵、可用供应商/模型和预算；缺失环境明确为未验证，不借缺失结果宣称候选已被淘汰。
- 最终只采用一个主要 Agent 运行时；模型适配使用其受支持接口，不建设未经场景验证的通用框架包装层。
- 框架[持久化能力](https://docs.langchain.com/oss/python/langgraph/persistence)只作为候选基础；实际磁盘保存、进程重启、事件续读与 F1/F2 幂等核对分别测试，不能用检查点存在推导外部操作恰好一次。
- 若入选方案需要子 Agent 或脚本沙箱，应同 Task 冻结能力/权限/部署及测试；未选中不宣称已支持，不以删去表图或报告需求收口。

## 主链路

1. **连续调查**：程序客户端创建会话并给定范围 → 加载技能 → 调用 F1 获取证据 → 写入 F2 → 流式给出事实/表图/缺口 → 接受补充或停止 → 保存报告引用。
2. **中断恢复**：取消、断连或重启 → 读取持久会话和关联操作 → 向 F1/F2 核对真实状态 → 展示未完成边界 → 按原授权显式继续或结束。

## Feature Tasks

- [ ] **T1：交付有可复核原型依据的运行时选择与会话契约，使独立部署、持续调查和状态恢复获得经过验证的实现基础。**
  验收 A1 及 A4/A5 的最小故障/归属原型；先输出候选契约再测试，冻结状态/事件、单会话串行、模型/费用预算、持久存储与最低部署，不能仅采用报告推荐名词。
- [ ] **T2：交付复用 Skills 和标准工具的专用调查服务，使普通会话客户端能连续验证异常并产生真实表图证据及报告。**
  验收 A2/A3；事件、缺失信息补充和资源预算覆盖主链路。
- [ ] **T3：交付可核对的会话持久化和操作生命周期，使取消、断连与服务重启不会丢失已保存证据或重复执行副作用。**
  验收 A4/A5；覆盖会话列举/隔离、重复消息、取消迟到事件、进程重启和工具响应丢失；区分会话继续与底层任务恢复。
- [ ] **T4：交付独立部署及真实模型验收，使专用 Agent 的运行隔离、诊断质量和成本可观测且无需产品工作台启动。**
  验收 A1～A6；覆盖实际交付的原生/容器方式及运维说明，不自动扩展未承诺矩阵。

## 验收锚点与依赖

| 编号 | 必须转成可执行断言或固定评判的结果 |
| --- | --- |
| A1 选型 | 冻结候选场景有实际执行记录和取舍；最终运行时能满足会话、Skills/MCP、事件与部署契约，未验证项不伪装已通过 |
| A2 诊断 | F3 真实 DNS 数据及反例通过；事实/候选/缺口分开，数值引用实际结果，表图和报告可重读 |
| A3 交互 | 流式进度、待输入、工具错误及预算耗尽有准确状态；会话列举/继续可用；同范围正常查询不反复请求许可，未回答的新授权不得执行 |
| A4 生命周期 | 真正重启进程后从磁盘恢复，按 F1/F2 请求身份核对响应丢失；取消阻止新操作且不提前报告底层停止；事件续读去重、过期游标重同步，迟到事件不串入新运行，不重复产生派生结果/报告 |
| A5 隔离 | 会话归属、并发消息、来源范围和产物引用不串用；重复提交去重，权限撤销后不能继续工具调用，报告冲突不覆盖人工版本；注入不能扩大权限，秘密不进入日志/结果 |
| A6 部署 | Agent 独立启停/升级时既有探索和 F2 报告可读；无需 F5 的程序客户端完成真实调查，记录质量、调用数、延迟和成本 |

- 真实模型、F1/F2 服务和 F3 评测集是验收依赖；统一运行时配置与隔离数据，不要求与本次调用无关的采集/Kafka 服务。
- 模拟用于生命周期故障注入和契约断言，不能替代真实模型诊断；镜像测试仅在交付容器契约时纳入。
- 实施时在工作台冻结具体命令、依赖、权限与支持矩阵；本轮没有启动原型或改变架构规则。
