# NPM 分族链路吞吐与分配优化

状态：待实施；T1～T5 尚未启动。优先级：P1。
前置：[npm-ip-family-pipeline](../archive/feat-npm-ip-family-pipeline.md)。
分析依据：[第二轮优化分析与方案](../../docs/npm-ip-family-optimization.md)、[分族成本报告](../../docs/npm-ip-family-cost.md)。

## 业务意图与 Non-Goals

为用 npm.basic 分析混合 IPv4/IPv6 离线或实时流量的用户，降低分族后新增的逐包分配、重复会话访问、
结束快照管理和单行结果编码成本；交付更高的处理吞吐，同时保留分族空间、原始处理顺序、全局身份、
三万会话容量、默认预算及全部已启用实体的正确输出和持久化。

不新增协议、分析指标、采集后端、并行 worker、异步写入或通用内存池/哈希表/字符串驻留设施。
不修改 SQL、12 个实体的名称/Schema、四后端表定义、纯虚插件接口及回调的借用语义。
不放宽容量、预算、校验、失败原子性或发布条件，不退回最大尺寸按值地址/键 variant。
不重写 TCP 重组、协议私有编码器、数据库驱动或 Baseliner；不提供兼容迁移或跨表原子提交。

## 问题与 Feature 边界

活动表/索引堆已下降，但当前每包临时键有独立堆对象，长 namespace 被复制两次；结束快照独立键和 lease 增加成本。
批次入场重复构造 Schema、重复 ValidateFull；持续会话的 Observe/SampleProtocol 重复查表。
Basic/Session 在 router 路径逐行构造 Arrow batch 再追加，输出样本中编码占插桩时间约 67%。
这些热点属于同一 packet → 会话 → 结果交付主链路；优化必须共同保留输入时序、拥有期、预算和发布保证。
历史无 -O 数据只定位问题；新 Feature 以实施前完整分族工作区的同配置 Release 快照验收。

## 核心数据与接口契约

### 输入、绑定与会话访问

Key4/Key6 保持当前具体族地址和拥有型 namespace；表项与独立保留数据不借用输入报文或临时字符串。
引入内部 `NpmPacketBindingView`：借用 Key4/Key6 的 KeyView，加方向、payload、transport 和标签事实。
无标签路径由当前具体族回调的栈键拥有；标签路径由两个预留完成的具体族键数组拥有，公共行保存族/索引。
键数组按实际族数量分配且计入输入预算；借用创建后不扩容，不按族重排处理或改变标签准入事实。
临时键不独立 make_unique；长 namespace 至多一次分配/复制，短 namespace 不产生键构造堆分配。
具体键移动构造避免必要拥有型转换中的额外复制；不声称 C++17 自动提供异构无分配 find。

内部 `NpmSessionAccess` 是 Observe 返回的短期访问句柄，关联具体表项、owner 与 session_id。
仅核心处理器在同次同步 Observe → SampleProtocol 段使用，不向模块暴露、不跨表变更、回调保存或异步工作。
持续 ACK 对已存在会话只进行一次逻辑键查找；采样和回调的顺序、迟到拒绝及实例匹配保证不变。
RST/FIN、tuple reuse、超时和 ICMP 引用保持自身查找与终结规则；不按固定测试数据更换哈希策略。

PacketFamilySchema/FilterSchema 使用线程安全不可变缓存；NPM 每批入场执行一次完整 Arrow 验证及全部族语义验证。
运行时预算判断复用规范 Schema，视图缓存具体子列访问；不以 trusted 标记绕过任意外部输入的验证。
自然对齐的族地址副本按实际数量保留和计费，不从任意 Arrow 字节地址强转分析对象。

### 拥有型结束批次

内部结束批次的最小数据组成如下；T1 以公共头声明和机器断言冻结具体类型，代码片段仅表示数据契约。

```cpp
struct NpmSnapshotRow {
    NpmSessionSnapshotFacts facts;
    packet::AddressFamily family;
    uint32_t key_index;
    int64_t observed_at_ns;
};
// NpmSessionSnapshotBatch owns vector<Key4>, vector<Key6>, vector<NpmSnapshotRow>
// and one RAII input-budget lease for its actual allocated storage.
```

生产主链路按拥有型批次保存实际族键与事件顺序，不给每条快照分配键对象或 shared lease。
EOF/超时先按候选数量准备全部数组、复制和预算，再一次提交水位/会话/索引变更；失败保持原状态。
逐包结束在当前处理批次的族存储中准备，模块结束回调仍按原时序执行，公共事件行不改变 observed_at。
批次复制深复制实际族数组和拥有型字符串并重新计费；独立保留单条记录同样有独立拥有和计费。
回调 View 只借用已冻结的族键，不依赖已经删除的活动表项；跨处理批次保留必须携带拥有型数据。
容量、字符串、事件行和 owner/lease 的成本统一计入 input budget；释放最后拥有者后精确归还。

### 有界结果交付

`INpmResultWriter`、协议 Emit、consumer 的既有纯虚接口不变；返回成功前同步拥有或编码借用的数据。
内部 `NpmResultDeliveryPlan` 在 Open 冻结每实体 descriptor、观察出口、consumer 出口与编码需求。
Basic/Session 中仅无观察且无 consumer 的实体跳过 Arrow 编码；校验、模块状态、revision 和结束处理仍执行。
Basic4/6、Session4/6 分别暂存拥有型结果，按实体复用批量编码器，不再每行创建 Arrow batch。
内部默认限制：每实体 512 行、全部 typed 暂存容量软上限 1 MiB；接收下一行前达到限制就排空。
单行超过软上限直接编码路由，仍受硬预算；暂存数组/string、Arrow、前台与数据库绑定的同时峰值均计费。
一批编码供前台与 consumer 复用，前台只按批追加到单个 pending builder 并 Finish，不做全量二次拼接。
协议模块的既有 RecordBatch Emit 保持同步校验/消费/复制，不承诺消除其已经发生的私有编码。
12 实体均保留正确路由，托管选择不被 observing 缩小；无出口的 typed 结果仍进行完整标量/UTF-8 校验。

typed pending 与前台 pending 分开计数；是否需要排空必须覆盖非观察实体，避免纯入库分支提前发布。
ProcessBlock、时间维护、正常 EOF/Stop 返回成功前排空已接受行，发布前全部相关结果与前台均完成。
末批成功后才 consumer Finish；失败/未知提交立即终结且不推进后续游标，保留实际已提交前缀。
取消/故障不补 EOF，不重试未知提交；清理所有暂存及预算，保留原始错误与 standalone Drain 的重试保证。
实体内发射顺序、revision、全局 ID、周期事实保持；不新增跨实体提交全序或跨表事务保证。
保留 Array/Buffer 的输出必须继续拥有 allocator、预算与插件生命周期，不以 task 销毁提前释放。

## 主链路

1. 混合输入 → 缓存 Schema/一次完整验证 → 对齐族地址 → 原行序具体键借用 → Observe/短期访问复用
   → 共享模块与原时序回调 → 需要保留时创建分族拥有型结束批次。
2. 模块结果 → 冻结的交付计划 → 有界具体族结果批量编码 → 前台与全部托管实体 → 末批排空
   → 分族发布或正常 Finish；失败/取消按已有终态和实际提交前缀清理。

## 验收契约

### 确定性结构与行为

- 现有会话包的临时键独立对象分配为零；短/长 namespace 分别零次/至多一次键构造分配。
- NPM 每批入场完整 Arrow 校验一次；仍拒绝错误 Schema、union offset、地址状态、NULL 和非法报文。
- 持续 ACK 每包一次逻辑会话查找，碰撞处理仍完整比较全部身份字段；不把哈希函数次数误当查找次数。
- 批量结束无逐快照键对象/lease 控制块分配，长 namespace 成本仍计费；深复制与失败均无悬空或部分提交。
- 512 行无中途时间边界的结果样本，编码/Consume 次数按实体与批次计，不能仍与结果行数一比一。
- 混合顺序、标签准入、唯一 ID、tuple reuse、协议采样、周期/终态与冷门族发布全部保持。
- 默认阈值下三万会话四生命周期 × 四族/观察组合通过，第 30,001 个会话按两族总量拒绝且状态不变。
- 四后端全部 12 实体地址无损读回；批量失败/未知提交停止发布，retained Arrow 与取消释放回归通过。

### 性能与完整 DoD

基线必须捕获实施前完整工作区（包括未提交源码），记录源码、依赖、编译参数和二进制摘要。
双方使用独立 Release build、相同 src 入口与主工作区第三方缓存，固定 CPU/96 字节/批量/模块/预算/出口。
每组至少七次独立进程、预热、版本交替；pps 主计时含处理、必要排空及输出释放，等价校验单独统计。
同时报告含校验/释放的历史口径、含 NPI 解码的端到端口径、范围、CPU、分配、实际堆/预算峰与 RSS。
比较排除真实 run 标识与生成时钟差异，其他业务字段、实体内行序和前台/托管行数必须等价。

| 同配置分族基线上的负载 | Feature 完成门槛 |
| --- | --- |
| 512 行 RST；v4/v6/mixed × Basic/Basic+Session | 每组吞吐中位数提升至少 20% |
| 30,000 活动会话 ACK；同六组组合 | 每组吞吐中位数提升至少 10% |
| 多地址/端口、递增时间、双向/payload、标签开关 | 每组吞吐下降不超过 3% |
| 三万会话表与索引堆 | 每族分布不高于优化前分族基线 |
| 三万会话 EOF 拥有型结束堆 | 每族分布相对分族基线降低至少 20% |
| 四后端托管结果 | 全量正确性通过，吞吐与提交成本逐后端报告 |

以上是待达成的验收目标，不是本轮结果；未达标需继续本 Feature 定位，不能仅凭 sizeof/分配计数宣告完成。
不确定差异落在采样波动内时不宣布通过；先以相同条件增加有效处理时长或稳定复测，不降低门槛。
不放宽默认 tracked/pending 预算，报告暂存/编码/绑定/保留输出重叠时的真实峰值。
当前标准全量 build、完整 CTest、四后端回归、ASan/UBSan/LSan、clang-format 和严格编译全部通过才完成。
